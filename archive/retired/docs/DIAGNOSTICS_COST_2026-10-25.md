## 基準、瓶頸與紅綠

發布完整腳本 439664 bytes，SHA-256 3960ac923f1cbd61d197e1b713c2c0e620debfcb40df1111cfc5af7d8dab3ae7。開始時工作目錄乾淨；最終 src-v2 與基準 Git 無差異，最終工具校準的確定性完整腳本亦逐位元組相同。版本、依賴與 Release 原件保持。

未插樁正常成本使用完整腳本、六十秒虛擬健康前置、六百次一秒 tick，每 tick 各完成 video／audio 請求。每倍速兩組暖機與十組交替計分；Recorder 的事故、容量與超大匯出另列，不併入正常播放。成本命令與測試不並行。這些數字包含離線模型及宿主工作，不是瀏覽器純功能成本或真實卡頓率。

獨立 profile 的正常播放路徑中，JSON.stringify 為主要具名熱點；每倍速十個虛擬分鐘觀察 9716 次序列化、7796 次編碼、204857757 UTF-8 bytes 及 3603 次深複製。這些計數包含整個 VM／宿主模型可觀察路徑，不把全部成本歸給 Recorder。程式檢查與成本契約另確認緩衝容量反覆計算：40 筆輸入觸發 103 次緩衝編碼。

兩個成本契約在未修改來源先失敗；候選以私有 WeakMap 保存去敏後自有緩衝列的精確 UTF-8 大小，保留 JSON 標點及 latest 重複值的容量計算，公開快照仍深複製。候選期間 diagnostics 143 案通過；各固定輸入的逐步快照／報告與完整腳本觀察、SDK、媒體及儲存摘要相同。候選 profile 的編碼變為 7196 次／170542790 bytes，約減少 16.75% bytes，深複製仍為 3603 次；工作量下降不足以代替 CPU 採用門檻。

## 工具期限校準與更正

新增實際案例總耗時守門後，發現 Node timeout 對持續同步／微任務工作不能單獨提供五秒證明。舊 profile-calibrated 與 profile-after 的超大匯出各四筆，僅 tick 總和已超過五秒，明確更正為無效；JSON 中保留原 validity，再以 durationAudits 追加有效性更正，沒有覆寫原數字。後續嚴格工具校準也拒絕四個同類案例，原非零結果保留。

輸入 v2 將匯出案例 reason／padding 的固定重複次數從 30000 改為 8000，仍有實際截斷正例；六個具名契約驗證事故、容量淘汰、超大匯出、清除與兩倍速。這是工具成本校準的新前提，不是產品候選調參或第三輪採用。v1／v2 全文與雜湊分開保存，舊配對不重新計分。

最終 schemaVersion 2 額外要求完整 caseDurationMs、精確六百筆樣本及完整零資源清理；在最後輸出前核對工具雜湊未變更。最終 profile 16 筆與未插樁成本 60 筆皆有效、行為一致，且兩側都是同一個 v2.1.36 產物；這只是已撤回候選後的工具校準。當時 12 個工具來源雜湊及完整產品輸入雜湊包含於逐案 JSON。
