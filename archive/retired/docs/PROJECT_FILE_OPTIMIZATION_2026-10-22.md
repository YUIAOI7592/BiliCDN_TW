1. **保護與盤點：** 保存逐檔用途／消費端快照及實體遍歷邊界，建立完整 verify 基準，再登記本計畫與當前工作。

3. **設定與工具：** 刪除已證明沒有現行輸入的舊屬性規則，明確區分通用 Prettier 排除與正式格式白名單；補足發行中繼資料、依賴宣告、lock 及實際工具版本的一致性契約。新工具行為先有正常／失敗對照，再實作並整合 verify。
4. **完整核對：** 對保留／修改／新增檔案形成最終對照，執行格式、型別、架構、完整測試、文件／公開封存與 verify；乾淨來源副本從 npm ci 重建驗證。核對同版本腳本逐位元組一致、Git 差異及遠端 main，按階段提交推送。

純文件階段執行文件、封存及差異檢查；工具變更階段執行型別、受影響 tooling 及完整 verify。必要來源修改一律使用 apply_patch。沒有證據支持的模組拆併、測試改名或私有原件搬動不做；任何必要變更仍須保持公開介面、狀態所有權、安全要求及儲存 schema。

不新增依賴、CI/CD 或執行期載入；版本維持 v2.1.27，不升版、不發布。BR-01、自然起因、已停止的歷史矩陣及瀏覽器驗收維持原結案範圍。公開、自動、來源、安裝及工具受限結果分開記錄，未執行不算通過。
