日期：2026-11-08（Asia/Taipei）。基準為 main `b6a3f34b81ec8cd4728e49627438e5e560e298d2`、v2.2.12；開始時工作目錄乾淨。本次只有私有研究工具與文件，不修改產品、正式測試、設定格式或政策，不升版、提交推送或發布。

## 研究結論

**本輪已取得具體的資格排除證據，但沒有取得提前重試的自然介入或效益樣本。** 指定片的兩個五分鐘窗口共觀察到 359 筆影音 XHR，其中 179 筆影片全部在正數 timeout 條件被排除。兩窗都沒有登記提前重試跟蹤、發放許可、arm、網站認領或替代送出的事件。

另有兩項必須一起解讀的事實：控制器的可播放緩衝始終高於六秒；`recovering` 在多數控制時點成立，但此欄同時包含恢復控制器與尚未結束的停滯段。不能從本輪推論「只要開放正數 timeout 就能改善播放」，也不能把該欄解讀為同樣次數的重載。

自然觀察、私有工具、離線模型分開結案：兩個正式窗口與清理完成；現場交接成本、完成預測校準與因果收益仍未識別。原六情境效用 FAIL 保留，既有 v2.2.12 R1 及熔斷驗收判定不變。

## 方法校準與偏差

離線七項方法契約涵蓋重複／亂序、保存失敗重讀、固定截止與尾段、時鐘倒退、容量、排程跳過及媒體替換／清理。IAB 合成哨兵確認非暫停觀察及跨呼叫保存，哨兵不計入產品事件。90 秒校準實際取得 453 列、79 筆所有類型 XHR 接受與 79 筆終止、36 次影片初始 guard 通過；觀察錯誤與溢位均零，截止晚 0.8 ms。

本次保留以下工具問題及修正，沒有因此追加校準或正式播放輪次：

1. 離線定位最初誤認 publish 為單行、Fetch 局部名稱為 `response`；改依完整本體的多行結構及 `response2` 定位，發生在 IAB 前。
2. 控制中心封閉根不能用一般座標 click；改用原生滑鼠。第一次開關座標落在 checkbox 左側，讀回仍 false；核對實際矩形後才啟用。正式窗口前狀態已為 true，不把未命中算設定故障。
3. 校準 timer 的小數截斷造成同一秒兩筆媒體讀值，90 秒共 110 筆。加入絕對秒槽去重與向上取整；一倍準備段 60／60、正式兩窗各 300 個唯一槽，沒有把校準重複值混入研究。
4. 工具函式閉包仍持有前窗純量游標，外部歸零沒有更新該閉包。一倍部分增量未取回，但來源端資料未溢位，結束前完整封存仍包含 1–1,112 連續序號，與已落地部分交叉去重核對。兩倍改用同一物件內的窗口／確認游標，增量與完整封存一致。這是持久保存時機偏差，並非來源事件遺失；若當時來源緩衝遺失，相關分母將不可用。
5. 請求 metadata 也有 `phase` 欄位；原列組裝覆蓋了工具同名欄位。所有窗內／尾段分類均獨立按 `atMs < durationMs`，不使用該欄。後續方法應改為分離名稱。
6. 每十秒可執行時保存，落後則跳過過期時點；一倍／兩倍最長取回間隔分別約 50.0／40.0 秒。來源容量保留且序號完整，不能把這些工具間隔計為播放停頓。工具往返讀取耗時一倍 9–30 ms、兩倍 9–29 ms；沒有量得每個觀察點的全部開銷，不宣稱零干擾。

後續四項私有核對補驗秒槽、尾段替代請求、跨窗游標及全部保存設定復原；不計入正式 2,140 案。正式窗口未使用暫停斷點，結束查詢沒有返回新增暫停事件；不以 Debugger 事件查詢取代媒體與來源序號完整性。

事件容量每窗 20,000、配對索引 4,096，正式實際事件 1,112／1,545，錯誤及兩種溢位皆零。每窗 300 筆媒體樣本，最大相鄰／邊界缺口約 1,006.8／1,007.1 ms；沒有大於 1.5 秒區段。截止回呼分別晚 9.0／6.9 ms，這些獨立邊界讀值不算窗內樣本。來源期限與三十秒尾段固定，尾段沒有新增研究分母。

## 交接成本、預測與離線反例

自然介入為零，因此許可後交接時間、實際替代總時間、完成預測誤差、期限誤判、節省停頓及額外下載均為**未識別**，不是零成本或效益通過。自然普通傳輸成功的耗時不能冒充替代傳輸結果。

未來有完整配對時沿用以下定義，全部以同一請求、同一觀察時點及適用時鐘計算：

```text
原路預測剩餘秒數 = 剩餘 bytes / 當時有效 bytes-per-second
替代預測總秒數   = 2 + 回應等待秒數 + 替代完整請求 bytes × 8 / 保守本文 bps
實際交接秒數     = 替代原生 send 接受時間 - arm 成功時間
實際替代總秒數   = 替代完成時間 - arm 成功時間
```

零進度的原路剩餘時間保持缺值；兩秒不能再次加到已包含交接的實際總時間。原路被中止後的繼續結果屬反事實，不能將原路預測與替代實際之差稱為實測收益。

使用鎖定 Node 26.8.1 重跑既有六情境及補充評估，命令不啟動服務、不讀正式 GM。原六情境 `valid=true / passed=false`、退出 1；慢場景改善與正常場景無多餘介入兩項仍未過，無停頓退步項仍成立。補充 `--optimization` 退出 0，只證明模型／計算契約。

獨立研究算式不匯入產品決策函式，核對 7,680 組資格／時間及四條片段軌跡的 16 段期限、buffer 與 bytes 守恆，全部一致；符合 1,076 組是合成格點數，不是現場率。輸入 SHA-256 為 `bc531b1a4b0fe97066c32f32a776a2953c40f1d9bbcc47b35771befba3f76770`。

| 同樣決策前提的不同未來 | 合成停頓差／完成時間差 | 意義 |
| --- | --- | --- |
| 原路持續慢 | 改善 14／15.7 秒 | 在該假設下有益 |
| 原路立刻恢復 | 停頓差 0、完成反而慢 2.1 秒 | 預測優勢不保證介入有益 |

## 建議順序與研究邊界

1. **先完成觀察方法的交付可靠性。** 後續共用窗口物件管理游標、分離 metadata.phase 與 windowPhase，保留每秒槽去重、來源硬截止、全量末次封存與冪等批次。若要給全站比例，須先補足其他通道的獨立分母；不能沿用本輪 XHR 子集冒稱全部。
2. **釐清恢復／停滯段抑制的實際持有者。** 先離線追查本輪所見「進度持續、緩衝充足、recovering 大多成立」的最小狀態路徑，區分預期保守段落與多餘保留；不直接刪除抑制，也不靠額外產品方法取樣。
3. **再決定是否設計正數 timeout 的提前重試方案。** 本輪確定它擋住全部已觀察影片，但同時緩衝不在適用區間，沒有證據顯示放寬必定有益。若提出方案，須先保護網站原生期限、動態寫入與還原、取消、一次送出及既有許可所有權；起播測速的正數 timeout 支持不能直接移植為提前重試權限。
4. **效益研究需要新的適用前提與對照。** 有合格在途影片、低緩衝與合法替代實傳證據後，才能核算交接及預測；沒有反事實資料仍只能給條件式收益。後續需另案定義新前提／期限，不因本輪零介入追加窗口、探測或改值湊樣本。

以上僅為後續建議，沒有啟動新修復或實測。既有提前重試抑制重封裝、真正跨頁、熔斷完整安裝故障注入、香港供片與歷史卡頓未因此結案，也沒有重測已通過的熔斷窗口。
