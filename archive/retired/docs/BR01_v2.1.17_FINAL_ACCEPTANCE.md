## 不通過窗口與校準紀錄

Auto1 第一個有效故障窗口：15秒後備援，約18秒 `ownership-ended`，沒有 Adapter 重載；這證明撤銷，沒有達到30秒救援及重載後15秒。早段連續捕捉，後續消費有 **29.458秒**空隙；釋放八個已失效攔截 ID 的錯誤保留，不能當完整時序或 CDN 健康失敗。沒有隱藏工具錯誤或回填事件。

背景操作期間，同片主頁自然 epoch0→1，後段 current request 資格為 false。新的 Auto1 seek2400重試保持51秒连续捕捉（最大241ms），但 held0、沒有 fallback／reload／deferred method，播放正常前進約54秒。這個窗口**不通過故障與晚到 SDK 驗收**；不是恢復失敗，也不能無證據宣稱 epoch 變化是新缺陷。

XHR 初次校準錯誤假設同步限制拋錯後必然仍 OPENED，隨後 send 拋 InvalidStateError，原結果完整保存。以真正 NativeXhr 的同步狀態突變重新校準後，八組安裝 hook 與原生的例外、狀態、事件及結果相同，無逾時；iframe、Blob URL、XHR與監聽器清理。此校準只修正驗收觀察器，沒有修改產品來源。
