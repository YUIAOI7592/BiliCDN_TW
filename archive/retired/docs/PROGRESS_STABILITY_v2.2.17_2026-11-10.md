## 政策與原案例映射

| 原問題／舊預期 | 新規則與保護 |
| --- | --- |
| 前進但間隔不足 1,000 ms 被排除 | 正數間隔不超過 2,000 ms 可提供一次有效觀察及實際間隔；999 ms 不再清空穩定度 |
| 只看十／二十個 tick | 重試與停滯穩定需十次且十秒；健康探索需二十次且二十秒；不依時間差補造次數 |
| 排程長缺口被當成停滯 | 仍有前進時只重建信用，不新增停滯；缺口不計入有效時間 |
| 重複或短負向讀值可建立段落 | 同時刻不改基準；不足一秒的負向讀值保留比較基準，確認時才開始段落，不倒推起點 |
| 整個 stall 物件等同正在恢復 | 分開 recoveryActive、stallPending、觀察分類及時間；十次／十秒後可在低緩衝完整評估，保留原 ID、期限及額度 |
| 健康額度按 tick 重開 | 高緩衝信用從第一筆合格觀察開始，十次且十秒才重開；未知間隔與先前低緩衝時間不回填 |
| 畫面把保留段落顯示為恢復 | 分別呈現正在恢復、等待穩定、播放穩定但保留額度、觀察不足；仍按需產生詳細文字 |

確認無進度保留原位置超過 0.05 秒、已知影格增加及控制身分條件。無效、倒退或不可用單調時間清除信用，不使用牆鐘補值；所有權變更先於時間去重。未知採樣不建立新控制動作，既有動作仍按絕對期限與所有權結案。

既有 seek／恢復案例保留名稱及副作用，新增前置完整觀察以建立新操作基準，再從確認停滯時核對原期限。BR-07 忽略 keyup 的案例特別斷言 14,999 ms 尚未備援、15,000 ms 正好備援，避免把延後斷言誤當期限保持。frame getter 案例依 Monitor 單次凍結改為一次，Recovery 原本的三次獨立讀取保持。

## 回歸與固定輸入對照

先保存九案紅燈結果：八個新預期失敗、一個既有行為控制通過，再修改執行期。後續增加時間、許可、健康探索及 UI 邊界。新增案例覆蓋 999／1,001、990／1,010、固定 999 ms、零起點、同時刻、倒退／非有限值、2,000／2,001 ms、牆鐘跳變、低緩衝穩定、實際 Recovery token、已用額度、pending 到期、未知間隔不回填及三頁共用模型。

使用固定 Git 基準非入口來源與新來源，對相同注入時鐘、播放器及請求輸入執行九種軌跡；未讀 Release bundle 或正式 GM 資料。

| 軌跡 | 基準 | 新版 |
| --- | --- | --- |
| 正常 1,000 ms | 無備援／重載 | 相同 |
| 999／1,001 ms 正常前進 | 一次多餘備援、段落殘留 | 零備援、無停滯段 |
| 固定 999 ms 正常前進 | 一次多餘備援 | 零備援，時間門檻前不取得資格 |
| 停滯後持續前進、緩衝五秒 | recovering 抑制、零 arm | stable-retained、一次合格 arm；沒有網站認領，沿原期限結案 |
| 停滯後高緩衝 | 結束段落，零備援 | 相同 |
| 真正無進度 | 同段一次備援、一次 reload | 同 ID／起點／截止與副作用序列 |
| 同時刻重複採樣 | 建立假停滯 | 不新增段落或許可 |
| 2,001 ms 後仍前進 | 建立假停滯 | 清除信用但不建立段落 |
| 半秒無進度 | 過早建立段落 | 一秒確認後才開始，不倒推 |

軌跡的 arm 是窄傳輸替身接受，不是實機網站交接或播放收益。既有正數 timeout 排除、Native 授權、黑名單／熔斷、保存／取消、影音隔離與同步重入由完整既有契約持續保護。原六情境提前重試效用 FAIL 不改判。
