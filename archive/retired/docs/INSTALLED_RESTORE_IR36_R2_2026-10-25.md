## 前提、成功條件與停止規則

各案例只用正常新文件自然具備的預算；故障前要求名義十秒健康播放、真正前景、身分完整、目標在當下緩衝外、精確新 video 請求命中及建立時受控 ID 寫入抑制。音訊與不屬本工具攔截的請求不持有。初始一倍為 S1／R1／B1／U1，二倍為 S2／R2／B2／U2。

| 類別 | 必須實際成立的故障前提 | 成功條件 |
| --- | --- | --- |
| S | 本次合法 SDK seek，原生位置距保存目標超過一秒；只忽略該次 seek | 一次以內原生位置補正，位置落地、倍速正確並持續播放 |
| R | 本次合法 SDK setPlaybackRate；呼叫時原生倍速與保存值不同 | 一次以內原生倍速補正，再持續播放 |
| B | 同一合法意圖中位置與倍速不符都成立 | 依序確認位置與倍速，各最多一次補正，再持續播放 |
| U | 本次 SDK seek 受控返回仍 pending，舊意圖未完成；可信暫停並切換 1↔2，操作修訂增加 | 舊意圖取消；晚到返回無舊 seek／setRate／play／補正，十五秒保持暫停與新倍速；不計救援成功 |

S／R／B 還要求同一意圖一次重載、命令滿一秒且非 pending／seeking、已知不符並仍有所有權才補正；原生位置誤差不超過一秒、倍速等於保存值，兩者確認後才 play。兩個合格原生進度樣本確認 recovered，再完整十五個一秒區段時間增加超過 0.05 秒，有影格計數時亦增加，沒有再次停滯或重載；原重載後十五秒期限不放寬。

總實際瀏覽器工作最多 120 分鐘，校準最多二十分鐘、案例及條件式重試最多八十分鐘，最後十五分鐘保留共同清理與報告；每次連清理五分鐘、arm 後九十秒、清理六十秒、U pending 八秒。每案最多 1024 媒體樣本、4096 事件、4 MiB 去敏資料。缺前提、事件、連續觀察或超量均 INVALID；有效案例才判 PASS／FAIL。修正工具或取得具體新前提後，無效案最多重試一次；首個確認產品缺陷即停止擴大。沒有新前提不追加窗口。

## 工具診斷與校準

以下 E 級校準在無 GM、無登入資料的自有 loopback 頁進行；不算產品通過。工具來源及每次實際載入 bundle 的大小／SHA-256 都在 JSON 的 toolSources 與 attempts.toolSource。公開工具只在明確 install 時工作，匯入不連網、不建立計時器或產品控制器。

- 可信尋位先 pointermove 顯示進度列，以實際幾何與 elementFromPoint 核對後可信按下／拖曳／釋放；E2／E3 捕獲 isTrusted=true、按住時 1955 秒。安裝版原生 seeking 可以合法回傳空的 opaque proof，產品 validateResumePosition 本來就允許；工具額外要求 proof 的判斷錯誤已修正。早先因此結束的 S2 窗口仍無效，不事後補判。
- 收集器以單一狀態保存游標、持有請求及錯誤，安裝開始前先在正確文件的 window registry 登記；失去遠端物件 handle 可由同一 key／executionContext 重新取得，安裝失敗留下可回收狀態。每批完整 await 並排至 hasMore=false。
- 使用精確 URL 及可證明的攔截階段判別自有暫停；保留不屬本工具的 Browser Use 文件回應，不擅自 continue。解除時先 Fetch.enable 空 patterns，再排空同一游標；Network.loadingFinished／loadingFailed 對應同一 networkId 才證明已終止。環境明確回覆 Fetch.disable 不支援後，沒有重試該方法或改權限。
- 期限獨立於心跳，最多四分鐘觀察並保留六十秒清理；第一次停止保存終點，租約過期不能續接成通過。主機最後使用三十秒租約及單次完整 await 的事件服務；R1 初次十二秒租約被跨呼叫空隙耗盡，原片段保留無效。
- 透明觀察實際共用 RuntimeIdPort.next，原樣保留 ID、receiver、返回與例外，登記 request／startup／challenge；EvidenceStore.record 只對受控 ID 提供拒絕寫入條件，其他原樣轉交。有限集合與晚到非同步寫入均有測試；不清空學習、不用舊快照覆寫新資料。
- SDK reload 在型別化 player-reload 事件與操作修訂之後、公開 reloadCount 更新之前即可執行。工具改用真正事件邊界辨識，E4 校準與契約重現此順序。不能把普通 recovered 當成重載；實際窗口中只有 B2 有一次合法重載。
- 尾端盤點受控 transport、route 工作、probe、record Promise、Measurement 狀態及私有 idle 的唯讀觀察。強制卸載時若尾端未完成，最新工具保留 ID／寫入抑制至文件卸載，其他自有包裝及計時器先解除；E5 實際證明 pending transport 的晚到兩筆仍被抑制。IR36-R2 首次採用的較早工具沒有這項保護，既有缺口不能由 E5 補回。

工具也分開記錄網站 play 與 PlayerAdapter 所有的 play，補正保留產品時鐘與原 commandAt；不替換媒體 getter／setter、可見性、網站 timeout 或政策。所有方法只還原仍由工具持有的描述子；SDK 原有 accessor setter 的包裝／還原另有契約。

初始校準含等待上界 766911 ms，五次補充的封閉短呼叫各小於十五秒，保守另計 75000 ms；合計上界 841911 ms，小於二十分鐘。這是可核對的含等待上界，純瀏覽器執行時間未獨立量測。E2 原 privateIdle 欄是佔位值，公開投影移除；真正私有 idle 核對位於各案 cleanup。沒有以佔位值證明校準通過。

## C01、資源與期限稽核

IR36-R2 首次等待尾端約四十五秒後，controlledRequests 仍為 1；舊 force cleanup 回報 restored=true，只表示當下方法被還原。它先解除了寫入抑制，不能證明該受控請求的晚到提交仍被阻擋。當下持久與記憶稽核的受控筆數 0 不能證明未來尾端。未清空學習或回寫舊快照掩蓋缺口，C01 因此 **INVALID**，不能排除該段晚到樣本污染。

S1 首次另留一筆誤認的 paused-ID 記帳；文件已關閉，不能把舊計數視為仍存活的請求，也不能補作自有解除證據。修正後各案尾端及自有包裝清理另存；B1／B2／U1／U2 的 finish 有 ready=true、抑制完整、受控記憶／持久筆數 0，然後才還原。清理後 guardIntact=false 是方法已還原，不是清理前失去抑制。

共同清理確認全部自有案例／控制頁關閉，IAB 原無其他分頁，結束分頁為 0、顯示狀態還原為隱藏；最後原生 paused=false、rate=2、位置 2012.036239。loopback 服務 PID 42656 已退出，5064 無監聽，偵錯物件群組與斷點按案釋放，CUA kernel 已重設。E5 在控制文件卸載前 guard active／intact，兩筆受控寫入均抑制、pendingWrites=0；不能用合成控制頁結果補回早期網站尾端。

瀏覽器工作起點 11:56:16.016Z；首次案例 12:10:53.990Z，末次 13:10:11.506Z。共同瀏覽器清理 13:15:07.815Z→13:15:07.866Z，服務核對止於 13:15:13.5136069Z；全輪含等待上界 4737498 ms（約七十九分鐘），案例及修正的牆鐘範圍也在八十分鐘內。各次嘗試均小於五分鐘，清理均小於六十秒；原始 arm 時間與首次停止點在 JSON，可見窗口在九十秒內結束。沒有把後續文件／Node 工作算成持續瀏覽器觀察，也沒有超時追加案例。
