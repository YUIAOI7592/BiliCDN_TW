## 來源定位與修復邊界

實際按鈕的事件處理器及閉包與 [control-center.ts](../../../src-v2/ui/control-center.ts) 一致：可信 click 執行 action，將當次 `report.value` 傳給 `GM_setClipboard`，僅同步拋錯時走原生備援。定位為 `#renderDiagnostics()` 的複製 action（目前第 341 行）及 `#button()` 的可信事件入口。

唯讀檢查實際 GM 綁定可見它將 content／info 交給 Tampermonkey 訊息通道；不直接讀取或控制擴充功能頁面。依 [Tampermonkey 官方契約](https://www.tampermonkey.net/documentation.php?q=GM_setClipboard)，格式可使用純文字資訊，完成回呼是管理器的通知。本次明確格式仍不生效，故沒有證據支持省略格式就是根因。

實際 UI 的資料傳遞依據為可信事件、已核對的完整本體、按鈕 action／GM 綁定及未變的文字區；沒有完整取得原 UI 呼叫的管理器內部處理序列。受控校準補得完成回呼，也無法定位管理器寫入端。不能把這些缺口包裝成已確認的程式缺陷或通過。

本計畫允許的原生備援條件是 GM 不可用或同步拋錯。本輪 GM 存在，受控校準正常返回並通知完成；未取得符合該條件的證據。盲目追加第二次寫入、逾時自動重寫或無條件改用原生 API 都可能造成晚到覆寫，且超出已確認的最小修復範圍，因此沒有實作。
