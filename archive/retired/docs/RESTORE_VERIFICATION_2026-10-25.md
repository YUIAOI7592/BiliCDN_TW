## 實作與唯一所有權

第一階段提交 770e2f7：Observer 在 SDK 方法取得、返回、拋錯及原生寫入前檢查媒體、播放器、核心、內容、控制修訂與目前資格。新 seek／pause／倍速操作、失去可見性、政策失效或 reset 後，不追加舊原生寫入及後續 play；原生 setter 中重入也不撤回或覆蓋新操作。網站方法的 receiver、參數、返回物件、例外及較新包裝保持原契約。

第二階段初版提交 0c39818，最終邊界修正提交 c0bd053。Recovery 唯一管理位置、倍速與進度階段、原期限及兩個一次性補正額度；Observer 唯一管理操作修訂、自有 reload、命令及原生落地證明。Adapter 只轉交具名介面，Runtime／診斷不建立第二份恢復狀態。

還原依序為 seek、原生位置確認且 seeking 結束、setRate、原生倍速確認、play、合格播放進度。同步正常 SDK 可在同 tick 完成；返回或 Promise resolve 不冒充原生成功。讀取拋錯、NaN、Infinity 或不可讀保持 unknown，不能以 SDK 快取或保守回退 0 通過。真正目標 0 與既有片尾裁切保持有效；已撤銷的位置還原明確略過，不重新提交舊目標。

每項 SDK 命令後至少 1000 ms，結果明確不符、非 seeking、非 pending 且所有權有效，才允許一次原生補正。原有 SDK 缺少／拋錯的原生備援使用同一額度，寫入前先消耗；拋錯、重入或未生效不重試。未知數值不能觸發推測補正，不新增原生 play 備援或 reload，不重新計時。

寫入驗證與後續只讀進度分開：progress 模式只能提供相符證明與本地所有者下的原生事實，不能延長寫入資格。失敗後最多保留一份有界的還原觀察，避免同所有者的錯位／錯速進度清掉失敗；它不保存操作 token、不授權寫入。新操作、所有者變更、reset 或新意圖沿原流程撤銷。

play 方法只取得一次，getter 後再次守門。位置落地至 play 之間的暫停時間不算播放時間，play 前另取原生位置／時間基準；同 tick 舊快照不能否定剛完成的還原。錯位、錯速、未知原生值、僅影格前進、尺寸或緩衝增加均不能取代正確還原及兩個有效樣本。

## 效益與非干預驗收

真實 Observer／Adapter／Recovery 的 ignored-seek、ignored-rate、both 與正常對照各做 1／2 倍；保存與寫入目標誤差不超過 0.000001 秒，位置確認在一秒內，倍速精確相等。真正 0 已正確時不補正。正常 SDK 不增加原生補正或 SDK 呼叫，無資格時後續副作用為零。

加入真實 Monitor／Runtime／Routes 的兩案以保存位置 978 秒重播，逐 tick 證據保存在 JSON：第一 tick 發出 seek，第二 tick 位置已落地並發出 setRate，第三 tick 倍速已落地才 play，第五 tick 取得兩個有效進度樣本並 recovered，符合六個既有監控 tick 內的門檻。這是指定合成核心就緒模型的結果，不是網站延遲量測。

成功案例再驗十五個一秒播放區段，時間增加大於 0.05 秒，有影格時必須增加，倍速保持且無額外 reload。尾段復發負對照確認持續播放判定會拒絕。原生補正無效時不 recovered，保留原十五秒期限，終止後再推進 120 tick 不重試。不能因測試預期「不恢復」而把失效情境宣稱為實際救援成功。

正式套件同時保留一般 6／12 秒、長 seek 15／30 秒、死核心四秒、重載後十五秒、長暫停三十秒、九十秒冷卻、生命週期兩次重載，以及新操作／晚到 Promise／影音隔離。決策、原選路、親和、探測、取消／派送、設定與儲存副作用未由新診斷或補正取得額外權限。清理先 stop／dispose 並驗證 timer／listener／subscription，再釋放 FakeClock。
