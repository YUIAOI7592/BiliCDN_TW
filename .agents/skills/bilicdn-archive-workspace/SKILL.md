# BiliCDN 工作區封存與清理

儲存庫根目錄位於本檔目錄向上三層。先核對當次授權、[AGENTS](../../../AGENTS.md)、[TODO](../../../docs/TODO.md)與活動工作；Skill 不提供新的刪除授權，也不恢復歷史執行器或測試。

## 分類與範圍

先讀[目錄與保存分類](references/layout-and-retention.md)。同時盤點實體檔案、Git 追蹤及忽略清單，不以 git status 或檔案日期代替用途判斷。區分原件、可重建副本、現行工具與未知資料，列出路徑、來源、所有者、活動狀態及預期處置。

刪除／移動前解析絕對路徑，確認限於已授權專案或明確暫存根，拒絕連結、逃逸及衝突。Windows 使用單一 PowerShell 的 LiteralPath 操作，不跨 shell 拼接破壞性命令。用途未知、無法排除活動使用或讀取失敗時保留該項並記錄缺口，繼續其他獨立合法工作。

## 執行順序

1. 釋放任務自有資源，固定原件與清單；必要操作紀錄保存於指定位置。
2. 按[壓縮與還原](references/packing-and-restore.md)建立公開／私有分離的包，獨立解壓並逐檔核對，新清單檢查通過後才刪除原位置及已證實可重建的副本。
3. 失敗保留原件與當次紀錄，不改保護登記或雜湊掩蓋問題；沒有完整證據不能宣稱已搬移、可還原或已清除。
4. 結案清理已驗證的還原與 staging 副本，避免整理本身累積大型暫存。主 .git 不 prune、不清 reflog、不重寫歷史，根 node_modules 不手動裁剪。

僅當次使用者或已批准計畫明確要求「刪除原操作文件且不留副本」，且確認不是受保護原件時，才依該範圍直接移除，以精確 Git 原文證明處理歷史引用。這不延伸到其他唯一證據；普通文件整理不啟動本流程。

## 驗證與交付

執行公開 archive:check；實際處置本機私有資料才加 --local，解壓完成後以 --restore-root 唯讀核對。只讀到清單不代表讀取原件成功。涉及文件／清單另依[文件維護](../bilicdn-maintain-docs/SKILL.md)檢查；工具變更仍須完整 verify。

交付處置清單、來源與雜湊、獨立還原結果、失敗／保留項目及實際減少量。分列 .work 減少、封存增加與整體淨減，不把本機壓縮稱為異機備份或 Git 歷史減重。產品未變更時不升產品版本。
