# BiliCDN_TW

BiliCDN_TW 是針對台灣網路環境維護的 Bilibili Tampermonkey 腳本，提供 CDN 選路、有限度的故障恢復。本專案的瀏覽器測試環境固定為 **Codex 內建瀏覽器＋Tampermonkey**。

正常模式預設從腳本的 **內建節點清單（Catalog）** 與 B 站當次提供的合法原始／備用網址選路。「允許參考 B 站原生來源」預設啟用；關閉後只使用 Catalog。

版本以 [release.json](release.json) 為準。安裝與操作見下文，完整驗證見 [TEST_REPORT](docs/TEST_REPORT.md)，目前工作見 [TODO](docs/TODO.md)。

瀏覽器驗證方式見 [IAB 測試方案](docs/IAB_TESTING.md)，各版實際結果與環境限制由 [HISTORY](docs/HISTORY.md) 追溯。

> [!IMPORTANT]
> **原作者與原始腳本：** [jiyunshi－Bilibili CDN 台灣優化](https://greasyfork.org/zh-TW/scripts/579776-bilibili-cdn-%E5%8F%B0%E7%81%A3%E5%84%AA%E5%8C%96)。本儲存庫源自原作者 MIT 授權腳本的個人修改專案；v2 是以 TypeScript 重新設計與重構的版本，並非原作者的官方版本。

## 安裝與更新

**目前為正式整合版。** 三頁控制中心、六個自動功能開關與香港節點已整合。v2.1.37／v2.1.38 保留原測試定位；提前重試的獨立效用仍為 FAIL，本版預設依使用者決策啟用，不代表效用驗收通過。

1. 在 Codex 內建瀏覽器的 Tampermonkey 環境進行本專案驗證；安裝方法依管理器提供的介面操作。
2. 開啟 **[安裝／更新腳本](https://github.com/YUIAOI7592/BiliCDN_TW/releases/latest/download/BiliCDN_TW.user.js)**，並在 Tampermonkey 確認安裝。也可從 [最新 Release](https://github.com/YUIAOI7592/BiliCDN_TW/releases/latest) 取得同一檔案。
3. 核對管理器內腳本版本。本專案測試保留其他已安裝腳本；若有互動影響，記錄實際環境與證據。
4. 重新載入 Bilibili 影片分頁，讓新版本生效。

腳本的自動更新網址固定指向本儲存庫的最新 Release。從 v2 更新會沿用既有 v2 設定與學習資料；v1 設定不會遷移，使用 v1 的使用者請停用舊腳本後安裝 v2。

已安裝時，可開啟同一「安裝／更新腳本」連結觸發更新，再重新載入影片。更新入口或管理器標示不能單獨證明新版已執行；驗證步驟見 [IAB 更新流程](docs/IAB_TESTING.md#8-修復發布與後續執行)。

GitHub Release 只提供 `BiliCDN_TW.user.js`。建置資訊、校驗碼與驗證紀錄保存在儲存庫的 [Release 目錄](Release)。

## 功能概覽

- **自動或固定 CDN：** 依合法候選與近期傳輸證據選路，也可指定內建節點。
- **影片與音訊分開判斷：** 量測、健康證據與故障處理分開記錄，避免互相影響。
- **有限度的測速與恢復：** 起播最多三個候選，有已知足速來源時保留一個探索名額；健康播放期間更新證據，遇到符合條件的故障時才嘗試備援或重建播放器核心。
- **保留播放選擇：** 倍速由使用者／B 站播放器決定，包含 2x；腳本依目前倍速估算需求。畫質與影片格式都由 B 站決定；腳本保留原始表示順序。
- **背景播放協助：** 減少頁面切到背景時因可見性事件造成的播放中斷；健康測速仍會檢查分頁是否真的在前景。
- **連線與節點控制：** 可阻止網頁使用 WebRTC、HTTPDNS，並設定個別 CDN 的可用性。

### 播放資料格式

總覽的緩衝、速度、需求及影音節點各依自己的資料顯示。影片尚未完成辨識時，已有的播放器尺寸會先顯示並標示編碼未確認；有速度但缺少需求時仍顯示速度。空值旁會說明等待影片資料、請求攔截未完整或尚無有效樣本等原因。節點欄只有觀察到回應才列回應主機，送出目標會標示等待回應。

安全吞吐使用目前路線主機的有效影片樣本，提示標明主機及目前傳輸／探測或歷史快取；樣本超過 24 小時不再使用。近期容量、單筆試用、歷史估計與待再驗證分開標示，歷史餘裕不當成當前已驗證能力。需求餘裕隨已確認影片碼率與實際播放倍率更新，缺少任一資料時保留缺值，不套用預設倍率或碼率。詳細計算與樣本期限見 [顯示契約](docs/ARCHITECTURE.md#控制中心資料流)。

支援 DASH 及 MP4／FLV `durl` 播放資料處理，保留原有分段順序、時長與大小，並為每段提供符合目前模式的主備網址。預設模式會從同段原始與備用來源中選擇可安全改寫的來源；只要有必要分段無法產生合法路線，整份已辨識的播放資料便不會部分改寫後放行。

番劇正片的 OGV `playview` 入口沿用相同處理；片頭 `pre/check/drm` 只辨識端點種類並原文通行，不改正片的內容週期。總覽亦顯示吞吐餘裕、起播等待及首段／中段探測摘要。這些改進的來源契約與實機驗證狀態見 [完整報告](docs/TEST_REPORT.md)。

控制中心的「最近播放資料」摘要，區分 Fetch／XHR、接納結果、DASH／MP4／FLV、影片／音訊／分段數量、上游 HTTP 狀態、數字錯誤代碼及拒絕原因。摘要不包含回應內容或簽名網址。原生來源開關、整體停用及固定 CDN 的既有模式繼續適用；在途測速結果不能覆蓋剛選定的固定 CDN。

## 開啟控制中心

可從以下任一入口開啟：

- Tampermonkey 選單中的「⚙️ 開啟 BiliCDN 控制中心」。
- B 站播放器設定面板中的「⚙️ 開啟 BiliCDN 控制中心」。

控制中心分為「總覽」「CDN」「播放設定」三頁。總覽保留可播放緩衝、保守吞吐、需求餘裕、影片／音訊回應、量測／恢復／提前重試狀態及詳細狀態。CDN 頁設定自動／固定模式、原生來源與各節點；播放設定提供六個功能開關與維護工具。

控制中心內聚焦按鈕後可用 Enter／空白鍵操作，Escape 關閉；表單與 Tab／Shift+Tab 保留瀏覽器原生行為。

### 自動功能與香港節點

以下六項在新安裝與缺值設定中都預設開啟，位於「播放設定」；升級保留既有明確 false。重設才完整套用新版預設。

| 功能 | 開啟／關閉效果 |
| --- | --- |
| 起播提前放行 | 合格候選可提早釋放；關閉仍等待全部候選或原三秒期限 |
| 健康中段探測 | 大小可靠時探測中段；關閉使用首段，大小與範圍驗證保持 |
| 備援家族分散 | 合格備援優先分散家族；關閉恢復原排序 |
| 慢請求提前重試 | 完整資格成立才要求原生 timeout，交由網站自行重試；關閉抑制新動作、撤銷待認領許可 |
| 阻止網頁使用 WebRTC | 沿用封鎖能力；關閉依所有權還原描述子 |
| 阻止網頁使用 HTTPDNS | 攔截已辨識請求；關閉後續請求走正常傳輸流程 |

OGV 正片入口持續啟用；片頭 pre/check/drm 只辨識端點並原文傳遞。

香港清單為 cn-hk-eq-01-03.bilivideo.com、cn-hk-eq-01-05.bilivideo.com、cn-hk-eq-01-01.bilivideo.com，作為一般 Catalog 節點預設可用；既有逐台覆寫保留。它們沒有特殊選路優先權，仍遵守來源授權、禁止、健康證據與親和規則。勾選只表示允許使用，實際回應主機見總覽。

### 三種使用模式

| 模式 | 可選來源 | 測速與自動恢復 |
| --- | --- | --- |
| 正常模式，原生來源關閉 | 安全產生的合法內建 CDN 主備網址 | 依播放狀態與限制執行 |
| 正常模式，原生來源開啟（預設） | 內建 CDN，以及 B 站當次提供的合法原始／備用網址 | 依播放狀態與限制執行 |
| 停用腳本 | 網站原本的請求 | 停止腳本改寫、主動測速與恢復 |

**原生來源開關預設啟用，會保存並同步到其他分頁。** 新安裝、缺值、非法欄位及還原預設使用新預設；既有明確 true／false 保留，讀取不自動改寫儲存。 關閉時，腳本辨識到的 B 站影音若無法安全改寫、沒有合法內建路線，或請求方式不適合改寫，會在送出前擋下請求，並顯示原因。若內建 CDN 與原始來源剛好是同一個主機，產生的網址可能相同，仍屬合法內建路線。

### 測速、封鎖與清除資料

手動安排測速、手動封鎖最近影片 CDN、香港定向驗證及專用授權已移除；自動健康探索與故障限制保留。以下清理與重設位於「播放設定」的摺疊維護工具，須於控制中心內確認。

| 控制中心操作 | 實際作用 |
| --- | --- |
| 清除測速紀錄、黑名單與故障標記 | 清除健康證據、節點限制與測速協調資料，保留功能設定 |
| 還原預設設定（不清除測速紀錄） | 重設功能與節點設定，保留既有測速紀錄 |

## 選路、測速與恢復規則

腳本在合資格起播時共用最多三秒的路線預測試，網站有設定 XHR timeout 也可參與；原 timeout 保持，測速等待另計，因此總等待時間可能增加最多三秒，實際放行仍受瀏覽器排程影響。網站自行取消仍會生效。健康播放時才安排一般探索，探索結果不會直接更換正在流暢播放的 CDN。

只用 Catalog 時，第一個實測達需求餘裕的起播候選可以提早釋放共用等待；有可靠資源大小時，健康探測可選擇對齊中段。已實測足夠的備援會優先分散主機家族，家族標記不代表已證明物理機房獨立。探測預算及細則統一見 [產品契約](docs/ARCHITECTURE.md#量測與恢復)。

停滯時可按一般／長 seek 政策切換合法備援並有限重載；有效可信目標與倍速可依所有權還原，真正位置 0 有效。新操作與資格失效會撤銷舊動作，不永久沿用最後非零位置。具體時點、額度、例外與取消條件統一見 [產品契約](docs/ARCHITECTURE.md#auto-救援與操作所有權)。

固定 CDN 是合法候選間的優先偏好；該台失敗或受限後，仍可使用其他合法備援並按原規則恢復，不會改寫你的固定設定。固定或勾選節點不解除禁止或熔斷。

CDN 是否可用取決於當時的網路、媒體與網站回應；指定節點、測速或自動恢復都不能保證每次播放成功。

## 卡頓或黑屏時如何排查

1. 查看總覽的緩衝、影音回應與恢復狀態，記錄當時倍速及操作。
2. 確認 Native 開關、固定 CDN 與禁止設定是否符合預期。
3. 到 [GitHub Issues](https://github.com/YUIAOI7592/BiliCDN_TW/issues) 提供腳本、瀏覽器／管理器版本及可重現步驟。

一般播放問題不要求診斷報告或完整 Network 匯出。若特定問題需要請求時序，僅取必要資料；不要公開簽名影音網址、權杖、Cookie 或原始網路匯出檔。

## 本機資料與隱私

設定與學習資料保存在 Tampermonkey 本機儲存空間。播放與主動測速仍會對 CDN 發送請求；腳本不提供事故錄製、診斷報告、複製或匯出功能。

| 儲存鍵 | 內容 |
| --- | --- |
| `bilicdn.v2.settings` | 功能、選路與節點設定 |
| `bilicdn.v2.restrictions` | 黑名單、故障與使用者節點限制 |
| `bilicdn.v2.routeEvidence` | 影片／音訊分開的主機健康證據 |
| `bilicdn.v2.meta` | 跨分頁測速冷卻與候選游標 |

完整簽名影音網址、路徑、查詢字串、權杖、播放器物件及事故時間線不寫入持久儲存。簽名網址只在目前播放生命週期的記憶體中使用。

總覽只使用當前狀態、最後一筆摘要與功能計數，不建立歷史錄製器，不讀寫剪貼簿。
