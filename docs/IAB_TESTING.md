# Codex 內建瀏覽器測試方案

適用目前 src-v2，版本以 [release.json](../release.json) 為準。本文件只保存方法，不構成啟動授權；目前批准範圍及停止／結案狀態只看 [TODO](TODO.md)。

**所有瀏覽器測試只使用 Codex 內建瀏覽器＋Tampermonkey。** 不改用外部 Chrome／Edge、獨立 Playwright／Puppeteer 或 headless 瀏覽器。Node 契約、型別、架構與建置另行執行。

同時僅一個自有 IAB 測試分頁；換片、更新及來源隔離共用或先關閉前一分頁再建立下一個。需要第二分頁的背景／遠端同步案例列未執行，不以歷史雙分頁方法覆蓋使用者最新界線。

所有方法先遵守 [AGENTS 永久執行禁令](../AGENTS.md#使用者永久執行禁令)：不使用本機網站服務、不要求使用者切換或維持前景，依已確認方法立即靜音並維持。Tampermonkey 查詢依 [現行瀏覽器界線](../AGENTS.md#瀏覽器工作界線) 按任務需要執行，不沿用已撤銷的探索禁令。使用者已明確允許 CDP；依當次工具實際回應執行，不把早先拒絕當成永久不可用，也不自行更改權限或繞過工具限制。命令 timeout 不代表權限等待一定會逾時拒絕，不承諾工具未提供的控制能力。舊方法與固定矩陣不構成新授權；必要前提無法滿足時記錄限制，停止該子項，繼續可獨立完成的工作。

依使用者已確認的方法，導覽／起播後立即操作真正播放器／媒體的靜音並讀回，後續持續維持靜音；2026-11-01 使用者再次明確澄清，沒有要求起播前已靜音。跨導覽預注入、腳本執行前暫停與起播前讀回不是必要門檻，缺少這些能力不得用來阻擋已可操作的真正靜音方法。換頁、換片或重建播放器後立即重新靜音並核對，不能以修改媒體 getter 偽造；保留音訊下載及與該案例相關的資料驗證。最初載入至靜音確認的區間不宣稱已全程無聲，也不計入播放驗收窗口。實際無法靜音或維持靜音時停止播放及相依案例；清理不得在仍播放時解除靜音，不要求使用者處理音量或喇叭。已確認的操作見 [原生靜音歷史紀錄](../archive/retired/docs/TEST_REPORT_HISTORY.md#2026-10-31依使用者更正靜音方法續行與下載工具超時)。

版本結果及工具能力由 [HISTORY](HISTORY.md) 追溯；來源、環境校準與實際安裝分開判定，歷史證據不能補算新窗口，也不能構成續測授權。

## 1. 範圍與證據層級

**一般播放與操作以產品行為判定：** 實際進度、暫停／尋位／倍速、錯誤、設定保存與 UI 操作各自驗證，不要求完整 Network、診斷報告或診斷工具成功。完整請求時序只適用於明確需要該證據的問題；不足時只限制該問題的結論，不能使獨立成立的播放或設定案例失敗。撤除功能沒有診斷頁、報告或原線對照驗收項目。

網站保留 [指定風景影片](https://www.bilibili.com/video/BV1tFZZBQE57/) 作歷史基準；當次已指定樣片時沿用，不為取得較好結果另搜尋替代片。只有獲准選片時才依下列展示樣片規則選入新片。只用 Auto 畫質，1 倍與 2 倍速分開。保持其他已安裝腳本與瀏覽器設定；使用者自行移除腳本則另記新環境，不回填舊窗口。不以強制畫質、停用其他腳本、改網站 timeout、媒體 getter、控制器或重設預算來製造成功。

| 層級 | 執行位置 | 可以證明 | 不能代替 |
| --- | --- | --- | --- |
| N：正式契約 | 現有 Node 套件 | 精確邊界、所有權與非同步交錯 | 瀏覽器原生行為與實際播放 |
| S：來源隔離 | 內建瀏覽器直接開啟自有本機 HTML／iframe | 在允許來源上實際完成的原生 API、可信輸入、修復來源與原生對照；`FakeClock` 僅在自有情境 | 已安裝 Tampermonkey singleton，以及因來源限制而未完成的 Fetch／XHR 網路行為 |
| I：實際安裝 | 內建瀏覽器＋Tampermonkey 的指定影片 | 完整本體、真正 singleton／hooks、Auto 播放與可觀察故障恢復 | 未發生的自然條件、其他站點／格式或其他瀏覽器 |
| E：環境校準 | 同一內建瀏覽器的自有控制頁與指定影片 | 操作、可見性、事件及攔截能力是否足以支持本案例 | 產品契約通過 |

自有控制頁直接開本機檔案，只含合成資料，不包含登入資料或簽名媒體網址，不啟動網站服務。S 的儲存使用注入介面與自有資料；不得把合成資料接到使用者正式 GM 持久資料。檔案來源不能完成的網路契約，列明限制，不另架服務、不拿 Node 模型代算原生通過。

### 門檻的適用範圍

門檻必須對應當次要求的具體斷言，說明依據、必要證據及缺失時受影響的結論；不能把方法清單全部當成每項工作的前置條件。下表是適用規則，不是每輪必跑矩陣。已批准的案例及斷言不因難以取證而刪除、降低或事後改列選測；若先前分類錯誤，另記更正依據，保留原結果，不補算 PASS。

| 門檻 | 何時必要、由何種證據判定 | 缺失時的影響範圍 |
| --- | --- | --- |
| 永久禁令與資料保護 | 所有操作遵守 AGENTS；播放立即靜音讀回，受控資料與自有資源依第 5 節隔離清理 | 停止違反界線的操作及相依案例，繼續其他合法工作；不要求解除禁令 |
| 管理器名稱／版本、保存的腳本副本 | 管理器識別、儲存內容或相容性的直接結論需要相應證據；按任務需要與工具能力查證 | 未取得時單獨列未驗證；不是已載入腳本本體、一般操作或產品接線的通用門檻，也不能替代頁面執行證據 |
| 完整載入本體與版本 | 宣稱頁面執行的是指定發行檔時，將當前載入完整來源與正式產物比對，區分載入包裝；UI 版本只證明顯示值 | 不宣稱完整本體一致；可另記實際 UI／播放觀察，不由公開下載替代載入證據 |
| 唯一實例、控制器引用及 hooks | 宣稱實例唯一或某段接線成立時，核對相應物件、引用與方法；產品 hook 自檢須標示證據來源 | 只限制相應接線／唯一性結論；不無限追加所有第三方 hook 鏈的來源認證 |
| 設定與恢復快照 | 核對該案例會改動或用來判定的欄位；有修改才保存原值及復原證據 | 不要求只讀本體查證先取得全部控制修訂、儲存內容或重載預算 |
| 設定操作、跨視圖與持久保存 | 操作以可信輸入及實際狀態確認；宣稱跨重載持久保存才另需新文件讀回 | 同頁往返不能冒充持久保存；未讀 GM 資料不阻止測試產品既有操作 |
| Network、事件游標與精確時序 | 請求歸因、次序、完整分母、攔截及精確期限斷言需要對應事件與連續性；普通 UI 不需要全流量 | 缺口只使依賴該段時序的斷言失效，不能否定獨立取得的本體、UI 或播放事實 |
| 真正可見性與背景轉換 | 驗證前背景切換或以可見性為資格的動作時，依第 3 節核對；未觀察轉換不能宣稱轉換通過 | 不要求一般入口或載入本體查證先通過 E04；不要求前景或開第二分頁 |
| 精確攔截、受控學習隔離與收束 | 故障注入前依第 5 節證明匹配、所有權、樣本抑制及解除；所有自有資源均需清理 | 不足時不開始該故障案例；一般只讀查證不必先建立故障注入平台 |
| 提案／認領／提交等完整動態協定 | 當次要求完整協定時須實際順序與結果；自然條件未出現列證據不足，不強制 tick、改時鐘或重開預算 | 方法存在與引用相同只證明接線，不能代算協定；反之，未發生整輪不否定已證明的方法接線 |
| 容量、淘汰、重入、取消及排序邊界 | 先按 N／S／I 指定需證明的層級；N 的精確契約與 I 的自然／受控行為各自判定 | 不把每項離線契約自動升格為安裝壓力矩陣；原已指定 I 的案例仍保留結果與缺口 |
| 樣片、倍率、時長及效益 | 凍結當次所需條件；三分鐘選片校準只用於選新展示樣片，1／2 倍分測只適用已納入的倍率；效益需對應比較設計 | 不為身分核對套用所有片單、雙倍率、舊十二窗或低緩衝研究；不縮短已指定窗口湊通過 |
| 工具能力與等待 | 僅確認本案所需能力，沿用仍有效的授權與同一實例證據；實際拒絕、等待與未知原因分開記錄 | 命令 timeout 不保證權限自動拒絕；不能因缺少這項保證判所有工具不可用，也不重複發起已受阻操作 |

新文件、腳本版本或實例改變會使相關載入／引用證據失效；工具重新連線本身不證明它們已改變。先核對當前文件及實例連續性，失效或無法確認的部分再重新取證，舊遠端物件 handle 不直接復用。換播放器只要求更新與該播放器有關的靜音、狀態及所有權證據，不自動撤銷無關的正式產物校驗。

「身分與接線核對」「完整動態協定」「播放／故障驗收」「效益研究」是不同結論。不得用其中一項成功覆蓋另一項缺口，也不得把所有尚未觀察的產品分支當成前者永遠不能完成的理由。沒有新證據需求的只讀檢查不啟動新播放窗口；安全、發布與文件門檻依 [開發驗證範圍](DEVELOPMENT.md#依變更選擇驗證範圍) 執行。

### 原生 API 的官方測試校準

僅確認瀏覽器原生 API 時，當次授權可涵蓋同一 IAB 分頁上的既有官方 [Web Platform Tests](https://wpt.live/xhr/) HTTPS 案例，歸 **E：原生 API 校準**。先閱讀實際測試、參數與資源，保存 harness 結果、日期及來源；不修改官方斷言、計時或結果。它不載入產品、不接正式 GM 資料，不能替代產品 S 隔離或 I 安裝驗收；需與 N 的產品契約及 I 的實際請求證據分別對照。原生方法的字串不能單獨作來源或行為證明。

本機檔案遭工具 URL 政策拒絕時，不用 CDP 重載本機內容、代理或其他瀏覽器繞過。既有官方測試是獨立校準來源，不是另建遠端服務或重新託管本機情境。工具超時與未取得的結果各自記錄；逾期取得的畫面不補算有期限的產品窗口，不因此否定其他已獨立成立的產品案例。

### 展示樣片選擇與唯讀窗口

優先選自然風景、海洋、動植物、微距、城市或 OLED 色彩展示，排除評測、教學、電影片段及固定測試圖。搜尋標示 4K／8K 的影片只形成候選；以既有帳戶確認正常播放、固定影片／分 P 至少三分鐘後才凍結，不購買或改帳戶設定，不逐片重複請求批准。標題宣稱與實際解析度、編碼、幀率分列；Auto 沒選到 8K 不算 8K 播放通過。

舊三階段效用矩陣的十二個五分鐘窗口、校準資格、前後置、430000 ms 會話截止與 120 分鐘預算，只適用當時輪次；方法原文保存在 [fede700 固定快照](https://github.com/YUIAOI7592/BiliCDN_TW/blob/fede7003e7c5056b9ca1a713dbee7266370e45e0/docs/IAB_TESTING.md#展示樣片選擇與唯讀窗口)，結果見 [第二輪十二窗](../archive/retired/docs/BUFFER_LIVE_EVALUATION_R2_2026-10-25.md)。它們不是新輪次的預設矩陣、期限或自動重跑授權。

當次計畫先凍結樣片、分 P、順序、倍速、窗口時長、前後置、必要觀察方式及截止；只有請求時序案例另凍結事件容量、讀取間隔；每窗完整連續，短呼叫只排空同一游標，不拼接獨立窗口。需要 Network 的案例才核對其連續性，與頁內採樣分別判定，媒體進度不能補算遺失的請求證據。工具自有觀察器有期限並登記清理，不呼叫產品 tick、新建控制器或重設預算。長等待、下載及取檔須有可觀察的外層截止，內部 timeout 參數不代表整個工具呼叫有界。

換所有者或現行救援介入的段落分列，不跨段配對。同一媒體且非暫停／尋位／結束／錯誤時，連續兩秒沒有合格進度另記卡頓事件，不直接歸因 CDN 或新版。十五秒仍播放不能單獨證明多餘介入；有指定後續觀察的案例須完整取得該段證據。

每份結果都寫明層級、版本、來源雜湊與情境。相同瀏覽器不會讓 S 自動變成 I。已發布版本的舊 Chrome 紀錄保留原證據身份，不改名冒充內建瀏覽器結果。

## 2. 開始前只做一次的環境確認

1. 記錄 HEAD、工作目錄狀態、release.json、可取得的工具版本與本案來源。完整本體查證另記目標附件及載入本體 SHA-256；一般操作未取得本體證據時明列限制，版本標頭不能代替完整本體核對。
2. 明確選取工具回報 `type=iab` 的瀏覽器；動態取得 browser／tab ID，不硬編碼歷史 ID。只透過目前工具文件列出且符合當次授權的介面取得證據，不另啟瀏覽器控制程序。已獲授權且當次可用的 CDP 可直接用於限定產品頁面的查證；管理器查詢同樣遵守工具與單分頁限制。
3. 依上表分開核對可見版本、載入本體、實例及 hook 證據；管理器識別與保存副本按當次斷言查證，未讀取不阻擋獨立成立的頁面產品結論。介面版本不能代替完整本體或私有執行接線；Debugger 查證仍受工具授權與其餘禁令約束。
4. 只記錄本案需要或會變更的原設定、播放狀態及控制／授權／重載額度，不把全套私有快照當通用前置。原始網址與播放器物件留在分頁記憶體，不輸出至報告。
5. 僅在無須本機服務且已授權的來源上證明精確 Request 攔截與清理，再開始網站故障案例；無合法可用來源或符合當次授權條件的工具能力就停止相關案例，不擅自建立遠端服務代替。既有 CDP 攔截與清理方法僅為歷史證據，不自動恢復故障窗口。
6. 只有依賴請求時序或故障攔截的案例才建立新單一 Fetch／Network 游標；前置請求、測試期間與晚到結果使用同一連續游標，持續分頁讀取至 hasMore=false，記錄 truncated／dropped／讀取空隙。背景觀察器需明列容量；丟棄過事件的窗口不能宣稱完整時序。
7. 確認沒有前輪遺留的自有請求、攔截、計時器、包裝或斷點。按上表處理文件／版本／實例改變及重連；同一有效實例的普通操作沿用既有證據，不重做全部準備。

一般頁面入口為播放器「設定 → 更多播放設定 → 其他設定 → 開啟 BiliCDN 控制中心」。封閉 Shadow DOM 可能不出現在工具的 DOM／AX 快照中；先用截圖確認，透過一般 Tab／Shift+Tab／Return 鍵盤導覽操作，每次以實際焦點與畫面核對。不因定位器無法讀取就判成入口不存在，不以注入事件或開啟私有閉包代替操作。一般唯讀 DOM 所回傳的媒體屬性須先與實際播放器顯示校準；若進度或音量顯示與屬性衝突，不把該讀值當成原生媒體狀態。靜音可由真正播放器音量 0 及靜音圖示讀回，暫停再以畫面、進度與產品狀態交叉確認。

取證能力調查須逐項區分一般畫面、公開 DOM、既有 console、頁面註冊工具及已觀察資產中繼資料。只使用當次文件列出的能力；清單包含 script 不代表支援匯出 script 本體，沒有日誌或註冊工具也不代表產品未載入。資產清單只保存必要類別與數量，不輸出簽名 URL。控制中心的 hook 狀態來自產品每次快照的安裝身分自檢，可作產品回報證據；完整載入本體、私有實例及完整協定時序仍須各自的證據，不能以此替代。能力調查結果與原案例覆蓋表記入 TEST_REPORT，不因某入口不可用就刪除案例，亦不以新增產品取證介面反證舊安裝版本。

故障窗口前只以不違反永久禁令的最小操作確認一般頁面操作、可信輸入、必要事件讀取與解除；不啟動本機服務或要求使用者切前景來排除工具阻塞。已有工作授權直接沿用；工具如遇權限閘門，保留具體限制，不反覆重試或繞過。工具成功返回也須核對實際結果；非同步操作完整結束後才採用結果。

新對話先檢查所需能力及證據是否仍有效，不因對話切換重做無關校準；受阻方法須有實際工具能力或授權變更等新前提才重試。一般工作授權、設定畫面的預設值或另一對話的成功，都不能解除禁令或代替本次能力結果；不直接修改權限檔繞過工具閘門，也不要求使用者再次批准已授權的同一操作。

[2026-10-11 可用性紀錄](../archive/retired/docs/IAB_TAMPERMONKEY_CAPABILITY_2026-10-11.md) 是當輪歷史能力證據，其中背景窗口已作廢，不能當成本方案的 E04 通過。後續各版結果由 [HISTORY](HISTORY.md) 追溯；本輪已取得的校準與完整身分可在同一有效實例內沿用，不重跑已通過窗口。

## 3. 前景偽裝與真正背景的校準

BiliCDN 的 [VisibilityAdapter](../src-v2/adapters/visibility.ts) 在 document **實例**覆寫 hidden=false、visibilityState=visible，讓網站繼續把頁面視為前景；安裝時另保存 prototype hidden getter，供自己的監控、量測與恢復使用。讀值分成三欄：

| 觀察欄位 | 方法與用途 |
| --- | --- |
| 網站所見 | 讀 document.hidden／visibilityState；啟用時保持 false／visible 是預期行為 |
| 經校準的瀏覽器原生狀態 | 使用來源已核對的原生 getter，觀察實際前景→背景→前景轉換 |
| Runtime 判定 | 讀真正 singleton 所連接的 `VisibilityAdapter.isActuallyVisible()`／相同注入查詢；背景應 false，返回應 true，不新增公開測試 API |

不能把第二、三欄當作兩份獨立的原生性證明，因為它們可能依賴同一個 getter；也不能只靠函式名稱或 `[native code]` 字串認定原生。

### E04 的實際步驟

原 A→B→A 雙分頁程序保存在 [固定歷史方法](https://github.com/YUIAOI7592/BiliCDN_TW/blob/fede7003e7c5056b9ca1a713dbee7266370e45e0/docs/IAB_TESTING.md#e04-的實際步驟)。依目前單分頁界線不執行該程序；不得要求使用者切前景、展開面板或讓工具搶焦點來補條件。

真正背景的證據要求保留：須核對原生 getter 來源及早於覆寫的實際時序，取得原生 false→true→false、Runtime 相對應狀態與網站偽裝讀值；工具 selectedTab、queued 回應及關閉面板都不足以證明背景。來源隔離的模型只證明 S 層邏輯，不能替代 I 層的原生轉換。不修改可見性 getter、不以合成 visibilitychange 或停用腳本製造通過。

未開始的背景案例列未執行；已開始而原生身分或連續觀察失效列 INVALID。無符合現行界線的新方法與當次授權，不重跑。

## 5. 故障注入、資料與清理

- 故障前先取得當前 video／audio 的歸因與精確請求範圍，只在記憶體比對 URL；不得以整個 CDN 主機或萬用媒體路徑阻擋音訊與其他網站工作。
- 僅持有送出前的自有匹配請求，不取消或重送已開始的網站請求。HTTPDNS／禁止路線案例先裝精確攔截，禁止拿真外送作封鎖驗證。
- gate 觀察器與游標在重新載入前準備；真實新請求、實際 pending 狀態與等待者必須有時間順序。若無法及時取得精確候選與安全攔截，停止該子項，不擴大攔截範圍或重設預算。
- 原生對照用自有合成頁的原生 Fetch／XHR；同片安裝版只改工具擁有的回應／Promise 邊界。合成 API 及媒體不得被寫入正式學習。
- 故障前先建立受控 transport／startup／challenge 工作 ID 的歸屬表與寫入抑制，沿用工作建立時的 ID，不只記錄網站 requestId。讀取完整資料只留本機記憶體，公開結果僅報數量與有界摘要。
- 每個可能提交證據的非同步尾端都收束後才解除抑制；若無法證明樣本隔離，該故障窗不得開始。清理期限內無法收束時，ID／寫入抑制保留至自有文件卸載，其餘自有包裝／計時器先清理並判 INVALID；不能先 detach 再以當下零筆數證明晚到寫入安全。不能事後清空全部學習資料掩蓋污染，也不能用舊快照覆蓋其他分頁新寫入。
- 設定變更只用產品既有命令；復原前確認該欄位仍為工具最後寫入的值，保留使用者或遠端的新修改。整體 reset／clear 不用於恢復測試初始狀態。
- 每個攔截立即登記 finally 清理。攔截生效期間持續處理事件，不在模型長等待時留住未服務的請求。事件截斷、失去連線或例外時先停止故障並收束自有請求；必要時卸載自有測試分頁後再撤除攔截。
- 跨工具呼叫的收集器以單一狀態物件保存游標、持有請求及錯誤，方法從該物件讀寫；不得假定重新指定外層變數會更新先前函式的閉包。先在正確文件的 registry 登記唯一 key，再安裝；參照遺失時以同一 executionContext／key 回收，不只依賴遠端 objectId。先在自有合成端點驗證跨呼叫續讀／清理，再開網站故障。先保存整批事件及可證明自有範圍的暫停 ID，再進行可能失敗的分類；自有範圍內不匹配請求立即放行，其他工具的 paused document response 不取得所有權、不擅自 continue。
- 游標建立與首次排空在同一有界呼叫完成；每批完整 await 至 hasMore=false，不留下跨呼叫的背景 Promise。持有、finally 解除及解除後突發排空先在自有來源驗證；模型返回空隙超過後端容量會使窗口截斷，不能靠媒體樣本補成完整傳輸證據。
- 精確攔截須對應當前媒體／核心的實際新 video 請求；舊 latestRequested 清單不能單獨證明會命中。沒有實際匹配／持有就沒有施加故障，不能把健康播放算成受控恢復通過。
- 有期限的觀察器由所屬資源自動截止，第一次停止時保存實際終點並清理 timer／listener／subscription；晚到 stop 不延長窗口。觀察終點、工具返回及操作收尾分開記錄，停止後的資料不能補進有效窗口。

- 新輪次若採固定讀取節奏，排程落後只跳至下一個未過期時點，不連續補抓冒充固定間隔。保存成功才推進續讀游標；部分保存失敗可重讀去重。固定來源截止，晚取回不能補造邊界讀值；容量溢位、尾段缺口及受影響結論須明列。[私有離線方法契約](../scripts/evaluation/README.md#後續取證方法契約) 不等於 IAB 校準，也不構成開啟新窗口的授權。
- 指標先移入並重新量測可見進度列；按下後立即核對 dragging，未成立即釋放，不能先等完整長按時間。讀取到網站前提失效時，在同一工具呼叫內解除攔截並收尾，避免模型往返期間繼續持有。
- 原生 seeking 下合法捕獲的有限目標可以沒有 opaque proof；以原生事實、可信操作及修訂判讀，不能額外要求產品原契約未要求的 proof，也不能修改媒體值補造合法命令。SDK reload 以實際操作、重載修訂及功能狀態辨識，公開 snapshot 可能稍後才更新；普通 recovered 不能當作重載成功。
- 保存方法完整描述子，只還原仍由工具持有的包裝；原為繼承方法則移除自有遮蔽，不覆寫其他腳本新包裝。
- 清理未完成會使本輪交付不通過，另列清理原因；不得先宣稱通過再把殘留交給下一輪。

### 解除受控延遲

解除受控延遲時立即清空自有攔截模式並核對後續新請求不再被持有。Network 截斷只使依賴完整時序的結論無效；獨立媒體採樣及產品操作結果保留。

## 6. 結果、期限與停止規則

每個案例保留窗口有效性與產品斷言，交付統一使用下列五種結果：

| 結果 | 使用條件 |
| --- | --- |
| PASS | 有效觀察與必要證據支持全部斷言，附預期／實際／證據 |
| FAIL | 有效窗口觀察到斷言不符；另列是否確認屬於 BiliCDN，不以傳輸失敗直接推定腳本缺陷 |
| INVALID | 已開始，但前提或證據完整性失效；不作產品判定 |
| 證據不足 | 已完成觀察，但必要自然條件或樣本未出現 |
| 未執行 | 因工具、安全前提、時間或範圍限制未開始 |

不使用「待驗收」取代具體結果。作廢不是產品失敗，也不是環境永遠不支援。完成門檻在開跑前依使用者要求及上述適用範圍區分核心必測與條件式證據，逐項寫明依據；不能把方法清單或歷史缺口全部升為核心。核心全部 PASS 且清理通過，才可宣稱核心完成。原已指定的必要項目 FAIL／INVALID／證據不足／未執行時明示該範圍未完成，不事後降級、刪行或補算通過。與當次斷言無關的管理器資訊及未啟動研究不需另請豁免才可繼續工作；條件式缺口仍列明，不宣稱全部行為或效用均已驗證。

- 同一版本／倍速／前提先做一個完整窗口；有效通過後不為湊次數重跑。
- 2026-10-13 已封存的 P01／P02 缺口不因自然前提或工具能力改變而自動恢復；須同時取得使用者明確恢復要求與指定影片自然 pending gate 的新前提。文件結案不將未執行情境填成 PASS。
- 無效窗口不自行補跑；只有當次明確允許重跑且取得必要新前提時才執行。不能從歷史方法繼承「可再跑一次」授權，相同無效方法不重複消耗時間。
- 開跑前凍結總時限、各階段上限與固定清理時段；以第一次最小工具檢查為 T0，保存 Asia/Taipei 時間與單調計時。後續階段不占用清理時段，餘額不足完成下一完整窗口就記未執行，不縮短或追加輪次。
- 工具往返、等待、更新及歸因操作都計入硬截止，不因個別 API 成功或內部 timeout 延長。能區分的純執行與等待另記，無分界則標未量測。批准或斷線破壞連續窗口時先作廢並清理，不拼接前後證據。
- 找到新確認缺陷時先收束故障、保存最小案例與正常對照、精確來源位置、根因與修正方向，再停止擴大本輪範圍。不得把修復、重新發布或新矩陣默默併入這輪文件方案。
- 若只剩工具或自然前提問題，交付終局的本輪結果與具體再開條件，不持續循環「再試一次」。
- 問題修復完成與整體核心驗收分開判定；正式契約、公開發布身分、實際安裝行為及效用證據各自列明。一次未再現不證明舊根因已解決，合法備援播放或香港音訊 206 不代算指定香港影片供片成功。

## 7. 證據目錄與重跑入口

新一輪的證據目錄使用 `.work/iab-testing/<日期>-<版本>-<短提交>-<輪次>/`，保留原始歷史工作目錄。下表是可按需採用的資料分工，不要求每個簡單查證都產生全部檔案；單一報告能完整記錄該案斷言、證據、限制與清理時可合併保存。需持續時序、續行或故障控制的案例仍保存相應欄位與原始證據，不以省檔省略。目錄於實際開跑時建立，本文件不宣稱已有一鍵 IAB 測試命令。

| 檔案 | 內容 |
| --- | --- |
| `BASELINE.json` | 基準、來源／產物雜湊、環境、版本／singleton、原狀態及預定 ID；不含 URL／憑證／播放器物件 |
| `CASES.json` | ID、層級、倍速、前提、開始／結束、有效性、五種結果、原因與證據指向 |
| `TIMELINE.jsonl` | 需要事件時序的案例保存連續有界事件摘要、游標／截斷／丟失狀態；寫出前去除網址、路徑、查詢、cookie、IP、物件 |
| `CLEANUP.json` | held／patterns、自有資源、方法所有權、設定復原、受控樣本匹配數 |
| `CHECKPOINT.md` | 已完成 ID、問題、剩餘前提與下一個具體步驟；不把過期 tab/object ID 當續行入口 |
| `RERUN.md` | 使用的工具能力、操作序列、預期值與清理步驟；需重新解析當前實例／請求身分 |
| `REPORT.md` | 當次範圍完成門檻、五種結果對照、確認缺陷、條件式缺口與清理 |
| `screenshots/` | 必要的可核對畫面；沒有畫面也不能用修改過的媒體 getter 冒充現場 |

新案例記錄 `id, level, version, bodySha256, rate, preconditions, validity, verdict, reason, expected, actual, evidence, cleanup` 及起訖、所需證據完整性與核心／條件式分類；未取得的本體雜湊、版本等明列未知及原因，不適用的倍率等明列不適用，不為填欄位追加操作或偽造值。verdict 使用上述五種結果；舊原件中的 VALID＋PASS／FAIL、INVALID＋null 保留原格式，不回寫遷移。時限案例另寫實際 T0、第一次合資格 tick、備援／reload／終止次數與時間。報告不只保存最後狀態，也保存因果順序。

重新連線先讀 CHECKPOINT 並依門檻適用表確認文件／實例；載入內容已改變或連續性無法確認時，重取相應本體及實例證據，不能復用舊 singleton handle。持續觀察的缺口要明記；即使本體相同，也不能把兩個分開窗口拼成一個完整時限。

## 8. 修復、發布與後續執行

修復時先建立正式失敗契約，按差異選取 N／S／I 案例。必要自動驗證依 [開發驗證範圍](DEVELOPMENT.md#依變更選擇驗證範圍)，完成對應套件、完整 verify 及 git diff --check；Codex Security 依安全敏感性或使用者要求另跑，不在 verify 內。

按 [AGENTS 發行規則](../AGENTS.md#發行規則) 完成已授權的功能修復交付；必要來源隔離同樣只在內建瀏覽器執行。公開產物核對與 I 層安裝驗收分別記錄。

當次需要且已授權更新時，先用內建瀏覽器的既有 [公開 latest 使用者腳本](https://github.com/YUIAOI7592/BiliCDN_TW/releases/latest/download/BiliCDN_TW.user.js) 入口，依允許的工具完成必要管理器步驟，再於新文件核對執行身分。使用者已表示更新完成或僅要求查證時，直接查證，不先下載、重新安裝或要求手動更新。中繼頁、管理器確認或保存副本均不能代替新文件的實際載入證據。只有必要步驟當次實際受阻且沒有已授權替代方式時，才說明具體限制及必要人工步驟；不改用外部瀏覽器、不繞過工具限制。

只有使用者明確要求恢復 BR-01，才重新安排其專項矩陣；先核對新差異及可沿用證據，不重測已通過項目。一次結束便保存總結與清理，不自動建立排程或下一輪。
