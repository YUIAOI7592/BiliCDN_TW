# Codex 內建瀏覽器測試方案

適用目前 src-v2，版本以 [release.json](../release.json) 為準。本文件只保存方法，不構成啟動授權；目前批准範圍及停止／結案狀態只看 [TODO](TODO.md)。

**所有瀏覽器測試只使用 Codex 內建瀏覽器＋Tampermonkey。** 不改用外部 Chrome／Edge、獨立 Playwright／Puppeteer 或 headless 瀏覽器。Node 契約、型別、架構與建置另行執行。

同時僅一個自有 IAB 測試分頁；換片、更新及來源隔離共用或先關閉前一分頁再建立下一個。需要第二分頁的背景／遠端同步案例列未執行，不以歷史雙分頁方法覆蓋使用者最新界線。

2026-10-31 起，所有方法先遵守 [AGENTS 永久執行禁令](../AGENTS.md#使用者永久執行禁令)：不使用本機網站服務、不要求使用者切換或維持前景、測試不得播出聲音。舊方法、固定矩陣及一般測試授權均不構成例外；必要前提無法在禁令內滿足時記錄限制，停止該子項，繼續可獨立完成的工作。

播放及可能自動播放的導覽前，先確認工具允許的實際靜音操作可確保無聲；沿用已確認的真正播放器／媒體靜音並讀回狀態，不把缺少某種跨導覽注入介面當成所有靜音方法都不可用。換頁、換片或重建播放器後立即核對並維持靜音，不能以修改媒體 getter 偽造；保留音訊下載與診斷驗證。無聲前提不足就停止相關操作，清理不得在仍播放時解除靜音，不要求使用者處理音量或喇叭。使用者更正後的當輪操作見 [原生靜音歷史紀錄](../archive/retired/docs/TEST_REPORT_HISTORY.md#2026-10-31依使用者更正靜音方法續行與下載工具超時)。

版本結果及工具能力由 [HISTORY](HISTORY.md) 追溯；來源、環境校準與實際安裝分開判定，歷史證據不能補算新窗口，也不能構成續測授權。

## 1. 範圍與證據層級

網站保留 [指定風景影片](https://www.bilibili.com/video/BV1tFZZBQE57/) 作歷史基準；當次已指定樣片時沿用，不為取得較好結果另搜尋替代片。只有獲准選片時才依下列展示樣片規則選入新片。只用 Auto 畫質，1 倍與 2 倍速分開。保持其他已安裝腳本與瀏覽器設定；使用者自行移除腳本則另記新環境，不回填舊窗口。不以強制畫質、停用其他腳本、改網站 timeout、媒體 getter、控制器或重設預算來製造成功。

| 層級 | 執行位置 | 可以證明 | 不能代替 |
| --- | --- | --- | --- |
| N：正式契約 | 現有 Node 套件 | 精確邊界、所有權與非同步交錯 | 瀏覽器原生行為與實際播放 |
| S：來源隔離 | 內建瀏覽器直接開啟自有本機 HTML／iframe | 在允許來源上實際完成的原生 API、可信輸入、修復來源與原生對照；`FakeClock` 僅在自有情境 | 已安裝 Tampermonkey singleton，以及因來源限制而未完成的 Fetch／XHR 網路行為 |
| I：實際安裝 | 內建瀏覽器＋Tampermonkey 的指定影片 | 完整本體、真正 singleton／hooks、Auto 播放與可觀察故障恢復 | 未發生的自然條件、其他站點／格式或其他瀏覽器 |
| E：環境校準 | 同一內建瀏覽器的自有控制頁與指定影片 | 操作、可見性、事件及攔截能力是否足以支持本案例 | 產品契約通過 |

自有控制頁直接開本機檔案，只含合成資料，不包含登入資料或簽名媒體網址，不啟動網站服務。S 的儲存使用注入介面與自有資料；不得把合成資料接到使用者正式 GM 持久資料。檔案來源不能完成的網路契約，列明限制，不另架服務、不拿 Node 模型代算原生通過。

### 展示樣片選擇與唯讀窗口

優先選自然風景、海洋、動植物、微距、城市或 OLED 色彩展示，排除評測、教學、電影片段及固定測試圖。搜尋標示 4K／8K 的影片只形成候選；以既有帳戶確認正常播放、固定影片／分 P 至少三分鐘後才凍結，不購買或改帳戶設定，不逐片重複請求批准。標題宣稱與實際解析度、編碼、幀率分列；Auto 沒選到 8K 不算 8K 播放通過。

舊三階段效用矩陣的十二個五分鐘窗口、校準資格、前後置、430000 ms 會話截止與 120 分鐘預算，只適用當時輪次；方法原文保存在 [fede700 固定快照](https://github.com/YUIAOI7592/BiliCDN_TW/blob/fede7003e7c5056b9ca1a713dbee7266370e45e0/docs/IAB_TESTING.md#展示樣片選擇與唯讀窗口)，結果見 [第二輪十二窗](../archive/retired/docs/BUFFER_LIVE_EVALUATION_R2_2026-10-25.md)。它們不是新輪次的預設矩陣、期限或自動重跑授權。

當次計畫先凍結樣片、分 P、順序、倍速、窗口時長、前後置、事件容量、讀取間隔及截止；每窗完整連續，短呼叫只排空同一游標，不拼接獨立窗口。頁內採樣與 Network 連續性分別核對，媒體進度不能補算遺失的請求證據。工具自有觀察器有期限並登記清理，不呼叫產品 tick、新建控制器或重設預算。長等待、下載及取檔須有可觀察的外層截止，內部 timeout 參數不代表整個工具呼叫有界。

換所有者或現行救援介入的段落分列，不跨段配對。同一媒體且非暫停／尋位／結束／錯誤時，連續兩秒沒有合格進度另記卡頓事件，不直接歸因 CDN 或新版。十五秒仍播放不能單獨證明多餘介入；有指定後續觀察的案例須完整取得該段證據。

每份結果都寫明層級、版本、來源雜湊與情境。相同瀏覽器不會讓 S 自動變成 I。已發布版本的舊 Chrome 紀錄保留原證據身份，不改名冒充內建瀏覽器結果。

## 2. 開始前只做一次的環境確認

1. 記錄 HEAD、工作目錄狀態、release.json、工具版本、目標腳本附件與執行本體 SHA-256。版本標頭不能代替完整本體核對。
2. 明確選取工具回報 `type=iab` 的瀏覽器；動態取得 browser／tab ID，不硬編碼歷史 ID。透過目前工具文件列出的 API 控制分頁與讀取 CDP，不另啟瀏覽器控制程序。
3. 核對實際 GM_info 的 scriptHandler、管理器版本、腳本版本；對照已載入完整本體、Runtime／`ControlCenter` 各一個實例與 hook 安裝狀態。Debugger 暫停僅用於身分取得，完成即解除；暫停中的時間不能算故障期限。
4. 記錄原設定、目前播放位置／速度、真正媒體狀態、控制修訂、授權與剩餘重載額度。只讀必要的有界欄位；原始網址與播放器物件留在分頁記憶體，不輸出至報告。
5. 僅在無須本機服務且已授權的來源上證明精確 Request 攔截與清理，再開始網站故障案例；無合法可用來源就停止相關案例，不擅自建立遠端服務代替。已知 raw CDP 需明列 Fetch／XHR resourceType；清理採 `Fetch.enable({patterns:[]})`，不能假設所有 CDP 命令都可用。
6. 建立新單一 Fetch／Network 游標；前置請求、測試期間與晚到結果使用同一連續游標，持續分頁讀取至 hasMore=false，記錄 truncated／dropped／讀取空隙。背景觀察器需明列容量；丟棄過事件的窗口不能宣稱完整時序。
7. 確認沒有前輪遺留的請求、攔截、計時器、包裝或斷點。版本、導覽、重新連線或執行實例改變時重做身分確認；同一實例的每個普通操作不重做全部準備。

故障窗口前只以不違反永久禁令的最小操作確認 JavaScript／CDP、可信輸入、事件讀取與解除；不啟動本機服務或要求使用者切前景來排除工具阻塞。已有工作授權直接沿用，工具強制批准仍須遵守；受拒絕的路徑不反覆重試。CDP 回傳必須檢查 exceptionDetails／Error subtype、實際方法與隔離審計；例外物件也可能有 objectId，不能據此判成功。非同步評估完整 await 後才採用結果。

每個新對話先依當次工具與正常權限流程作最小校準，保留當次回覆。舊對話的 CDP 拒絕不能直接當作本次結果；同一對話與來源若已遭保存拒絕，仍須有實際權限變更等新前提才重試。口頭工作授權、設定畫面的預設值或另一對話的成功，都不能代替本次能力結果；不直接修改權限檔繞過工具閘門。

[2026-10-11 可用性紀錄](../archive/retired/docs/IAB_TAMPERMONKEY_CAPABILITY_2026-10-11.md) 是當輪歷史能力證據，其中背景窗口已作廢，不能當成本方案的 E04 通過。後續各版結果由 [HISTORY](HISTORY.md) 追溯；本輪已取得的校準與完整身分可在同一有效實例內沿用，不重跑已通過窗口。

## 3. 前景偽裝與真正背景的校準

BiliCDN 的 [VisibilityAdapter](../src-v2/adapters/visibility.ts) 在 document **實例**覆寫 hidden=false、visibilityState=visible，讓網站繼續把頁面視為前景；安裝時另保存 prototype hidden getter，供自己的監控、量測與恢復使用。讀值分成三欄：

| 觀察欄位 | 方法與用途 |
| --- | --- |
| 網站所見 | 讀 document.hidden／visibilityState；啟用時保持 false／visible 是預期行為 |
| 經校準的瀏覽器原生狀態 | 使用來源已核對的原生 getter，觀察實際前景→背景→前景轉換 |
| Runtime 判定 | 讀真正 singleton 所連接的 `VisibilityAdapter.isActuallyVisible()`／相同注入查詢；背景應 false，返回應 true，不新增公開測試 API |

不能把第二、三欄當作兩份獨立的原生性證明，因為它們可能依賴同一個 getter；也不能只靠函式名稱或 `[native code]` 字串認定原生。

### E04 的實際步驟

原 A→B→A 雙分頁程序保存在 [固定歷史方法](https://github.com/YUIAOI7592/BiliCDN_TW/blob/fede7003e7c5056b9ca1a713dbee7266370e45e0/docs/IAB_TESTING.md#e04-的實際步驟)。依目前單分頁界線不執行該程序；不得要求使用者切前景、展開面板或讓工具搶焦點來補條件。

真正背景的證據要求保留：須核對原生 getter 來源及早於覆寫的實際時序，取得原生 false→true→false、Runtime 相對應狀態與網站偽裝讀值；工具 selectedTab、queued 回應及關閉面板都不足以證明背景。來源隔離的模型只證明 S 層邏輯，不能替代 I 層的原生轉換。不修改可見性 getter、不以合成 visibilitychange 或停用腳本製造通過。

未開始的背景案例列未執行；已開始而原生身分或連續觀察失效列 INVALID。無符合現行界線的新方法與當次授權，不重跑。

| 類型 | 制定與判定依據 |
| --- | --- |

## 5. 故障注入、資料與清理

- 故障前先取得當前 video／audio 的歸因與精確請求範圍，只在記憶體比對 URL；不得以整個 CDN 主機或萬用媒體路徑阻擋音訊與其他網站工作。
- 僅持有送出前的自有匹配請求，不取消或重送已開始的網站請求。HTTPDNS／禁止路線案例先裝精確攔截，禁止拿真外送作封鎖驗證。
- gate 觀察器與游標在重新載入前準備；真實新請求、實際 pending 狀態與等待者必須有時間順序。若無法及時取得精確候選與安全攔截，停止該子項，不擴大攔截範圍或重設預算。
- 原生對照用自有合成頁的原生 Fetch／XHR；同片安裝版只改工具擁有的回應／Promise 邊界。合成 API 及媒體不得被寫入正式學習。
- 故障前先建立受控 transport／startup／challenge 工作 ID 的歸屬表與寫入抑制，沿用工作建立時的 ID，不只記錄網站 requestId。讀取完整資料只留本機記憶體，公開結果僅報數量與有界摘要。
- 每個可能提交證據的非同步尾端都收束後才解除抑制；若無法證明樣本隔離，該故障窗不得開始。清理期限內無法收束時，ID／寫入抑制保留至自有文件卸載，其餘自有包裝／計時器先清理並判 INVALID；不能先 detach 再以當下零筆數證明晚到寫入安全。不能事後清空全部學習資料掩蓋污染，也不能用舊快照覆蓋其他分頁新寫入。
- 設定變更只用產品既有命令；復原前確認該欄位仍為工具最後寫入的值，保留使用者或遠端的新修改。整體 reset／clear 不用於恢復測試初始狀態。
- 每個攔截立即登記 finally 清理。攔截生效期間持續處理事件，不在模型長等待時留住未服務的請求。事件截斷、失去連線或例外時先停止故障並收束自有請求；必要時卸載自有測試分頁後再撤除攔截。
- 跨工具呼叫的收集器以單一狀態物件保存游標、持有請求及錯誤，方法從該物件讀寫；不得假定重新指定外層變數會更新先前函式的閉包。先在正確文件的 registry 登記唯一 key，再安裝；參照遺失時以同一 executionContext／key 回收，不只依賴遠端 objectId。先在自有合成端點驗證跨呼叫續讀／清理，再開網站故障。先保存整批事件及可證明自有範圍的暫停 ID，再進行可能失敗的分類；自有範圍內不匹配請求立即放行，其他工具的 paused document response 不取得所有權、不擅自 continue。
- 游標建立與首次排空在同一有界呼叫完成；每批完整 await 至 hasMore=false，不留下跨呼叫的背景 Promise。持有、finally 解除及解除後突發排空先在自有來源驗證；模型返回空隙超過後端容量會使窗口截斷，不能靠媒體樣本補成完整傳輸證據。
- 精確攔截須對應當前媒體／核心的實際新 video 請求；舊 latestRequested 清單不能單獨證明會命中。沒有實際匹配／持有就沒有施加故障，不能把健康播放算成受控恢復通過。
- 有期限的觀察器由所屬資源自動截止，第一次停止時保存實際終點並清理 timer／listener／subscription；晚到 stop 不延長窗口。觀察終點、工具返回及操作收尾分開記錄，停止後的資料不能補進有效窗口。
- 使用 [IabEventCollector](../scripts/iab-event-collector.mts) 時，每窗建立新實例，注入文件化的 CDP capability 及明確 ownsPaused。releaseHolding 先清空 patterns，再排空同一游標，保留還原／尾端事件服務；放行錯誤保留請求所有權，只有相同 networkId 的原生 loadingFinished／loadingFailed 才能另行確認結束。cleanup 完成不會消除已記錄的窗口錯誤。
- 指標先移入並重新量測可見進度列；按下後立即核對 dragging，未成立即釋放，不能先等完整長按時間。讀取到網站前提失效時，在同一工具呼叫內解除攔截並收尾，避免模型往返期間繼續持有。
- 原生 seeking 下合法捕獲的有限目標可以沒有 opaque proof；以原生事實、可信操作及修訂判讀，不能額外要求產品原契約未要求的 proof，也不能修改媒體值補造合法命令。SDK reload 以真正 player-reload 事件／操作修訂辨識，公開 snapshot 可能稍後才更新；普通 recovered 不能當作重載成功。
- 保存方法完整描述子，只還原仍由工具持有的包裝；原為繼承方法則移除自有遮蔽，不覆寫其他腳本新包裝。
- 清理未完成會使本輪交付不通過，另列清理原因；不得先宣稱通過再把殘留交給下一輪。

### 剪貼簿校準與保護

獲准進行複製案例時，先用自有頁的唯一合成文字，以真正複製、真正貼上及預定讀回方式證明共同通道，再操作產品。`Get-Clipboard -Raw` 讀空且正常退出不代表內容真的為空；需另查原生存取是否成功。隔離層外讀回也不能假設與 IAB 使用同一剪貼簿；通道不一致的舊觀察見 [P05 修復報告](../archive/retired/docs/P05_COPY_FIX_REPORT.md)。

覆寫前須能完整保存並復原實際複製通道的原格式；Windows 快照不能假設涵蓋 IAB 剪貼簿。原內容只留記憶體，復原前核對內容與可用變更序號仍屬本輪，保留使用者的新寫入；真空資料與空文字分開。通道沒有格式或序號能力時列限制，不以盲目清空取代復原。

完整保存實際通道全部原格式、讀回及依所有權復原三項前提都成立，才操作產品複製；否則列未執行，繼續可獨立完成的匯出案例。不要求 PowerShell 必須讀回，也不使用會先改寫剪貼簿的工具貼上方法。IAB 真正 Ctrl+V 與剪貼簿 API 的適用性須由當次共同通道校準支持；與同一次已建立的完整報告逐字比較，不重新產生即時報告。只有原生對照證明平台換行轉換，才另列 LF／CRLF 相等，不 trim 或重新序列化。校準期限由當次計畫指定，不據通道限制修產品、升版或重複寫入。

實際 UI 不符即記本次不通過，但必須另分來源缺陷與管理器／通道未定位。GM 返回或完成回呼不是讀回證據；不得因逾時再寫一次或無條件使用第二條寫入路徑。直接 API 合成探針不是原生 UI 驗收，須有明確授權且只作定位；沒有新前提不重跑。

### 解除延遲與剪貼簿寫入

解除受控延遲時立即清空原生攔截模式，確認之後沒有新的 `Fetch.requestPaused`，再觀察恢復。不得保留攔截並仰賴不連續輪詢逐筆放行。Network 截斷的完整時序窗口作廢；獨立媒體採樣只保留其直接證明的結果，不補算傳輸矩陣通過。

P05 原生優先寫入須由真正可信按鈕操作立即啟動；當次完整報告以 API 讀回與真正 Ctrl+V 雙重逐字比較，不 trim、不重序列化、不以完成提示代替讀回。完整項目快照只留記憶體，寫入收束且所有權相符才復原；原內容不寫檔。來源記憶體 UI 與實際安裝的完整本體／唯一 singleton 分列。已通過結果及先前 GM 通道限制見 [P05 修復報告](../archive/retired/docs/P05_COPY_FIX_REPORT.md)。

## 6. 結果、期限與停止規則

每個案例保留窗口有效性與產品斷言，交付統一使用下列五種結果：

| 結果 | 使用條件 |
| --- | --- |
| PASS | 有效觀察與必要證據支持全部斷言，附預期／實際／證據 |
| FAIL | 有效窗口觀察到斷言不符；另列是否確認屬於 BiliCDN，不以傳輸失敗直接推定腳本缺陷 |
| INVALID | 已開始，但前提或證據完整性失效；不作產品判定 |
| 證據不足 | 已完成觀察，但必要自然條件或樣本未出現 |
| 未執行 | 因工具、安全前提、時間或範圍限制未開始 |

不使用「待驗收」取代具體結果。作廢不是產品失敗，也不是環境永遠不支援。完成門檻在開跑前區分核心必測與條件式證據；核心全部 PASS 且清理通過，才可宣稱核心完成。獲准不阻塞結案的條件式缺口仍逐項列出，不宣稱全部行為或效用均已驗證。必要項目 FAIL／INVALID／證據不足／未執行時明示本輪未完成核心驗收，不刪行湊通過。

- 同一版本／倍速／前提先做一個完整窗口；有效通過後不為湊次數重跑。
- 2026-10-13 已封存的 P01／P02 缺口不因自然前提或工具能力改變而自動恢復；須同時取得使用者明確恢復要求與指定影片自然 pending gate 的新前提。文件結案不將未執行情境填成 PASS。
- 無效窗口不自行補跑；只有當次明確允許重跑且取得必要新前提時才執行。不能從歷史方法繼承「可再跑一次」授權，相同無效方法不重複消耗時間。
- 開跑前凍結總時限、各階段上限與固定清理時段；以第一次最小工具檢查為 T0，保存 Asia/Taipei 時間與單調計時。後續階段不占用清理時段，餘額不足完成下一完整窗口就記未執行，不縮短或追加輪次。
- 工具往返、等待、更新及歸因操作都計入硬截止，不因個別 API 成功或內部 timeout 延長。能區分的純執行與等待另記，無分界則標未量測。批准或斷線破壞連續窗口時先作廢並清理，不拼接前後證據。
- 找到新確認缺陷時先收束故障、保存最小案例與正常對照、精確來源位置、根因與修正方向，再停止擴大本輪範圍。不得把修復、重新發布或新矩陣默默併入這輪文件方案。
- 若只剩工具或自然前提問題，交付終局的本輪結果與具體再開條件，不持續循環「再試一次」。
- 問題修復完成與整體核心驗收分開判定；正式契約、公開發布身分、實際安裝行為及效用證據各自列明。一次未再現不證明舊根因已解決，合法備援播放或香港音訊 206 不代算指定香港影片供片成功。

## 7. 證據目錄與重跑入口

新一輪建立 `.work/iab-testing/<日期>-<版本>-<短提交>-<輪次>/`，保留原始歷史工作目錄。這是命名方案，目錄與執行器須在實際開跑時建立；本文件不宣稱已有一鍵 IAB 測試命令。

| 檔案 | 內容 |
| --- | --- |
| `BASELINE.json` | 基準、來源／產物雜湊、環境、版本／singleton、原狀態及預定 ID；不含 URL／憑證／播放器物件 |
| `CASES.json` | ID、層級、倍速、前提、開始／結束、有效性、五種結果、原因與證據指向 |
| `TIMELINE.jsonl` | 連續有界事件摘要、游標／截斷／丟失狀態；寫出前去除網址、路徑、查詢、cookie、IP、物件 |
| `CLEANUP.json` | held／patterns、自有資源、方法所有權、設定復原、受控樣本匹配數 |
| `CHECKPOINT.md` | 已完成 ID、問題、剩餘前提與下一個具體步驟；不把過期 tab/object ID 當續行入口 |
| `RERUN.md` | 使用的工具能力、操作序列、預期值與清理步驟；需重新解析當前實例／請求身分 |
| `REPORT.md` | 當次範圍完成門檻、五種結果對照、確認缺陷、條件式缺口與清理 |
| `screenshots/` | 必要的可核對畫面；沒有畫面也不能用修改過的媒體 getter 冒充現場 |

新案例的必要欄位：`id, level, version, bodySha256, rate, preconditions, validity, verdict, reason, expected, actual, evidence, cleanup`；另保存起訖、事件完整性及核心／條件式分類。verdict 使用上述五種結果；舊原件中的 VALID＋PASS／FAIL、INVALID＋null 保留原格式，不回寫遷移。時限案例另寫實際 T0、第一次合資格 tick、備援／reload／終止次數與時間。報告不只保存最後狀態，也保存因果順序。

同一內容改寫後重新連線時，先讀 CHECKPOINT 並重新核對安裝本體，不能復用舊 singleton handle。持續觀察的缺口要明記；不能把兩個分開窗口拼成一個完整時限。

## 8. 修復、發布與後續執行

修復時先建立正式失敗契約，按差異選取 N／S／I 案例。必要自動驗證仍為 typecheck、architecture、npm test、verify、git diff --check；Codex Security 依安全敏感性或使用者要求另跑，不在 verify 內。

按 [AGENTS 發行規則](../AGENTS.md#發行規則) 完成已授權的功能修復交付；必要來源隔離同樣只在內建瀏覽器執行。公開產物核對與 I 層安裝驗收分別記錄。

Tampermonkey 更新先用內建瀏覽器開啟本儲存庫既有 [公開 latest 使用者腳本](https://github.com/YUIAOI7592/BiliCDN_TW/releases/latest/download/BiliCDN_TW.user.js)，再於新載入的指定影片核對完整本體與 singleton。更新中繼頁本身不等於安裝成功。不能把「擴充功能介面受限」直接推論成「公開更新入口不能使用」。只有當次可用入口實際受阻或仍需使用者完成確認時，才請求必要手動步驟；不改用外部瀏覽器、不繞過工具限制。

只有使用者明確要求恢復 BR-01，才重新安排其專項矩陣；先核對新差異及可沿用證據，不重測已通過項目。一次結束便保存總結與清理，不自動建立排程或下一輪。
