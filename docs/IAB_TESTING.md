# Codex 內建瀏覽器測試方案

本文件適用 `src-v2/`，版本以 [release.json](../release.json) 為準，只維護驗收方法。當次使用者要求與 [TODO](TODO.md) 決定範圍及停止狀態；文件整理、工具恢復或發布不構成新一輪授權。結果由 [TEST_REPORT](TEST_REPORT.md) 保存，歷史由 [HISTORY](HISTORY.md) 追溯。

**瀏覽器測試只用 Codex 內建瀏覽器（IAB）＋Tampermonkey，同時僅一個自有測試分頁。** 換片、更新與來源隔離共用該分頁，或先關閉再建立下一個；需要第二分頁的案例列未執行。不改用外部 Chrome／Edge、獨立 Playwright／Puppeteer 或 headless 瀏覽器。

所有操作遵守 [AGENTS 永久執行禁令](../AGENTS.md#使用者永久執行禁令)：不使用本機網站服務、不要求前景或搶焦點、依已確認方法立即靜音並維持。Tampermonkey 探索禁令已於 2026-11-13 撤銷，管理器可依任務需要查證；CDP 亦已有使用者授權。實際可用能力仍以當次工具文件及回應為準，不繞過工具閘門，也不重複要求已有授權。

靜音在導覽／起播後立即操作真正播放器／媒體並讀回，換文件或播放器後重新核對；初始載入至確認的區間不計入播放驗收，不宣稱全程無聲。不追加起播前靜音、跨導覽預注入或腳本執行前暫停門檻。保留音訊下載及相應驗證；無法靜音或維持時停止播放及相依案例，清理不在播放中解除靜音。[原生靜音歷史紀錄](../archive/retired/docs/TEST_REPORT_HISTORY.md#2026-10-31依使用者更正靜音方法續行與下載工具超時)只供方法追溯。

## 1. 範圍與證據層級

一般播放以實際進度、暫停／尋位／倍速、錯誤及 UI 行為判定；設定操作與跨重載保存分開。完整 Network、私有快照或診斷報告不是通用前置，撤除的診斷／剪貼簿功能不列入現行驗收。

| 層級 | 證明範圍 | 不能代替 |
| --- | --- | --- |
| N：正式契約 | 既有 Node 套件中的精確邊界、所有權與非同步交錯 | 瀏覽器原生行為、實際播放 |
| S：來源隔離 | IAB 自有本機 HTML／iframe 中實際完成的來源與原生對照；FakeClock 限自有情境 | Tampermonkey 安裝實例、未完成的原生網路行為 |
| I：實際安裝 | 指定影片中實際取得的本體、實例／hooks、操作及恢復證據，各自判定 | 未發生條件、其他站點／格式／瀏覽器 |
| E：環境校準 | 同一 IAB 的控制頁、官方原生測試或指定影片中，本案所需操作／事件／攔截能力 | 產品功能通過 |

S 自有控制頁直接開本機檔案，只用合成資料及注入儲存，不接正式 GM 資料、登入資料或簽名媒體網址。檔案來源無法完成的網路契約列明限制，不另架服務或拿 N 代算 S／I 通過。同一瀏覽器也不會讓 S 自動成為 I；歷史 Chrome 紀錄保留原身分。

### 門檻的適用範圍

先定義當次斷言，再取必要證據。下表不是每輪必跑清單；已批准的案例不能因難取證而刪除、降級或改列選測。前提／證據缺失只影響相依結論；更正錯誤分類時保留原判及更正依據，不補算 PASS。

| 要證明的結論 | 必要證據與界線 |
| --- | --- |
| 所有操作合法且可收束 | 遵守永久禁令及第 5 節資料／資源保護；不為一般只讀查證建立故障平台 |
| 管理器識別、保存內容或相容性 | 按斷言直接查證管理器；未取得單列未驗證，不阻擋獨立成立的播放、本體或接線結論 |
| 載入完整指定發行檔 | 當前完整載入來源與正式產物比對，區分包裝；UI 版本、公開下載及管理器副本均不能替代 |
| 唯一實例、控制器引用或 hooks | 對應物件、引用及執行證據；產品自檢明示來源，不無限追加第三方 hook 鏈認證 |
| 設定操作與保存 | 可信輸入、實際狀態及受影響原值；跨重載保存另需新文件讀回，同頁往返不代算，不強制讀全部 GM 資料 |
| 請求歸因、完整分母、次序或精確期限 | 對應連續事件、時間基準及精度；Network 缺口不否定獨立取得的 UI／播放／本體事實 |
| 真正前背景與可見性資格 | 依第 3 節取得本案所需狀態；轉換斷言才要求完整轉換，不把 E04 當一般查證前置 |
| 受控故障及恢復 | 第 5 節的精確目標、實際注入、學習隔離及清理；必要前提不足就不開始 |
| 完整動態協定 | 提案／認領／提交等實際順序及結果；方法引用只證明接線，自然條件未出現列證據不足 |
| 容量、淘汰、重入、取消或排序 | 先指定 N／S／I 層級，不把每個 N 契約自動升格為 I 壓力案例；已指定 I 的缺口保留 |
| 播放窗口或效益 | 凍結所需樣片、倍率、時長與比較設計；身分查證不套用全片單、雙倍率或歷史研究 |

只取得本案需要或會變更的設定／控制／額度快照，不要求全部私有狀態。新文件、版本或實例改變時更新受影響證據；工具重連先查文件及實例連續性，不直接復用舊遠端 handle，也不無條件重做全部核對。換播放器更新靜音、狀態及所有權證據，不撤銷無關的產物校驗。

### 原生 API 的官方測試校準

已授權的原生 API 調查可在同一 IAB 分頁執行既有 [Web Platform Tests](https://wpt.live/xhr/) HTTPS 案例，列 E。先讀測試、參數及資源，保存來源、日期與 harness 結果，不改官方斷言或計時。它不載入產品、不接正式 GM 資料，不能替代 S／I。

本機檔案遭 URL 政策拒絕時，不以 CDP、代理或另一瀏覽器繞過；官方測試是獨立來源，不是重新託管本機情境。超時、未取得結果及逾期結果分列，逾期畫面不補算有期限的窗口。

### 展示樣片選擇與唯讀窗口

保留 [BV1tFZZBQE57](https://www.bilibili.com/video/BV1tFZZBQE57/) 作歷史比較基準；當次已有片單就沿用，不因結果換片。獲准選新展示樣片時，優先自然風景、海洋、動植物、微距、城市或 OLED 色彩，排除評測、教學、電影片段及固定測試圖。4K／8K 標題只形成候選，以既有帳戶在固定影片／分 P 正常播放至少三分鐘後凍結；不購買、改帳戶設定或逐片重複請求批准。

只用 Auto，已納入的 1／2 倍分開驗證；標題與實際解析度、編碼、幀率分列，Auto 未選 8K 不算 8K 通過。保持其他腳本及瀏覽器設定；使用者自行改變環境另記，不回填舊窗口。不改網站 timeout、媒體 getter、控制器或重設預算製造成功。

播放／效益計畫凍結影片、分 P、順序、倍速、時長、前後置、觀察方式與截止；請求時序案例另定事件容量及讀取節奏。每窗完整連續，不拼接分開窗口。換所有者或救援介入的段落分列，不跨段配對。同一媒體且非暫停／尋位／結束／錯誤時，連續兩秒無合格進度可依本方法記卡頓；這是觀察分類，不是產品觸發門檻或 CDN 歸因。十五秒仍播放也不能單獨證明多餘介入，指定的後續觀察須完整取得。

舊十二個五分鐘窗口、430000 ms 會話截止及 120 分鐘預算只屬當時輪次；[固定方法快照](https://github.com/YUIAOI7592/BiliCDN_TW/blob/fede7003e7c5056b9ca1a713dbee7266370e45e0/docs/IAB_TESTING.md#展示樣片選擇與唯讀窗口)與[原始結果](../archive/retired/docs/BUFFER_LIVE_EVALUATION_R2_2026-10-25.md)供追溯，不作新輪次預設。

## 2. 開始前只做一次的環境確認

同一有效環境只確認所需能力；換對話或重連不自動重測。新拒絕／等待、歷史成功及當次成功分開，不因早先受阻永久排除已授權能力。

1. 記錄 HEAD、工作樹、產品版本、可取得的工具版本及本案來源；完整本體查證另記正式附件與載入來源 SHA-256，未知明列限制。
2. 依當次工具文件及回報識別 **IAB**，動態取得 browser／tab ID，不硬編碼舊 ID 或假定必有 `type=iab` 欄位。不另啟控制程序；CDP／Debugger 與管理器查詢沿用現有授權及單分頁界線。
3. 按第 1 節核對本案身分、操作及原值，確認前輪自有請求、包裝、計時器、攔截與斷點已清理。只讀本體查證不新開播放窗口。
4. 要做故障才校準對應邊界的匹配、事件、解除與隔離；需要請求時序才建立連續事件收集。具體規則見第 5 節，不要求每種故障都先建 Request 攔截。
5. 僅做必要最小操作確認工具能讀回實際結果。非同步結果完成後才採用；實際權限閘門、超時與原因未知分開記錄，不改權限檔、繞過限制或反覆發起受阻操作。命令 timeout 不保證整個工具呼叫或權限等待有界；缺少此保證也不代表所有工具不可用。

產品入口以實際畫面為準：播放器設定區的「⚙️ 開啟 BiliCDN 控制中心」，或 Tampermonkey 已註冊的同名選單。網站歷史路徑為「設定 → 更多播放設定 → 其他設定」，網站改版時不把此路徑當產品契約。封閉 Shadow DOM 可能不出現在 DOM／AX 快照；可用截圖及可信鍵盤／指標操作，每步核對焦點與結果，不搶焦點，也不以注入事件或呼叫私有閉包冒充 UI 操作。

媒體讀值須能對應真正播放器；若 DOM 進度／音量與畫面衝突，不據此宣稱原生狀態。可依已確認的方法讀回播放器音量 0 與靜音圖示；暫停以畫面、進度及產品狀態交叉核對。資產清單含 script 不等於取得完整本體，缺少 console／註冊工具不等於未載入；hook 狀態是產品自檢，不替代外部 Network、唯一實例或完整協定證據。只保存必要類別、有界摘要及脫敏結果。

## 3. 前景偽裝與真正背景的校準

[VisibilityAdapter](../src-v2/adapters/visibility.ts) 安裝時先取得 `Document.prototype.hidden` 描述子，再嘗試於 document 實例覆寫 `hidden=false`、`visibilityState=visible`。覆寫可能失敗；保存的 getter 也可能已被其他程式包裝，因此「有保存」不等於「已證明原生」。

| 觀察欄位 | 意義與限制 |
| --- | --- |
| 網站所見 | 成功啟用偽裝時為 false／visible；不能證明真正前景 |
| 經校準的瀏覽器狀態 | 核對來源、realm、getter 與實際文件關係後，取得本案所需原生狀態 |
| Runtime 判定 | 真正實例所接的 `isActuallyVisible()` 或注入查詢，代表產品決策輸入；不新增公開測試 API |

Runtime 優先呼叫保存的 getter；缺 getter 時回退讀 document.visibilityState，例外或未安裝／已解除時可回報 visible。其 true 不能單獨證明真正前景，亦不能與同一 getter 的讀值算成兩份獨立證據。函式名稱、`[native code]`、工具 selectedTab、queued 回應及面板隱藏都不足以證明原生性或背景。

### E04 的實際步驟

E04 用於完整前景→背景→前景轉換，取得原生 hidden 的 false→true→false、相應 Runtime 狀態及網站偽裝讀值。核對 getter 來源及與安裝時捕獲的關係；不把「一律須在腳本之前預注入」當通用要求，document 實例覆寫本身不會改寫 prototype getter。

[歷史雙分頁方法](https://github.com/YUIAOI7592/BiliCDN_TW/blob/fede7003e7c5056b9ca1a713dbee7266370e45e0/docs/IAB_TESTING.md#e04-的實際步驟)不符合現行單分頁界線，不執行；也不要求前景、展開面板或搶焦點補條件。S 模型不能替代 I 原生轉換，不修改 getter、合成 visibilitychange 或停用腳本製造通過。沒有合法方法就列未執行；已開始而來源或連續性失效列 INVALID。一般當下可見性資格只需相應有效狀態，不要求先完成整個 E04。

## 4. 固定驗收矩陣

「固定」指凍結當輪範圍，沒有通用必跑矩陣。先列案例 ID、版本／差異、N／S／I／E、沿用證據、前提、事件順序、預期返回／狀態／副作用、精度及清理。完成門檻按當次要求區分核心與條件式證據，不在執行中無限加項。

產品時間、資格及額度以 [現行契約](ARCHITECTURE.md#auto-救援與操作所有權) 為準：N 驗精確邊界，瀏覽器列採樣與 tick 誤差；S 使用同一自有來源的正常／失敗對照，I 按斷言取得安裝證據。自然起因不是所有救援修復的隱含門檻，普通 UI 也不必完成完整故障平台。

v2.1.20 的 E／S／B／P／C 矩陣見[重整前原文](../archive/retired/docs/DOCS_BEFORE_REORGANIZATION_2026-10-17.md#docs-iab_testing-md)，結果由 HISTORY 追溯；舊門檻不自動適用新版本或恢復舊案例。

## 5. 故障注入、資料與清理

### 注入前：目標與學習隔離

- 按案例選邊界：網路故障先歸因當前 video／audio 的實際新請求，只在記憶體比對精確 URL，不用整個 CDN／萬用媒體路徑阻擋；SDK 案例僅包裝所需回應／Promise 邊界，保留 receiver、參數、例外及所有權。原生對照使用自有合成頁。
- 請求攔截僅持有送出前的自有匹配請求，不取消或重送已開始的網站請求。HTTPDNS／禁止路線先裝精確攔截，不拿真外送作封鎖驗證。gate 案例在重新載入前建立觀察，保存真實請求、pending 及等待者的順序；無法安全命中就停止，不擴大範圍。
- 對所有可能受注入影響的 transport／startup／challenge 工作建立歸屬與寫入抑制，沿用工作 ID，不只記網站 requestId；合成／受控樣本不得進正式學習。完整資料只留記憶體，結果只記數量與有界摘要。
- **既有抑制能力須逐路徑核對。** [suppressEarlyRetryEvidence](../src-v2/application/routing/route-coordinator.ts) 只控制提前重試證據；一般 evidence.commit 在其判定之前，不能拿它當所有健康學習的隔離。方法文件不代表現成工具已具備完整抑制，證明不了就不開始該故障窗。
- 注入、持有、跨呼叫續讀及失敗解除先在合法自有情境校準。校準邊界須對應實際方法，不要求無關的 Request 攔截或本機服務，也不新增產品取證介面反證舊版。

### 執行中：事件與所有權

- 建立事件流時凍結起點、容量、讀取節奏及截止，前置、窗口與晚到事件維持可追溯的續讀關係。拉取型游標建立後立即完成首次排空；若 API 提供 `hasMore` 就持續讀至 false，訂閱型介面則核對其序號／遺失訊號，不假定 Fetch、Network 必共用一個游標。記錄截斷、丟棄與空隙，沒有遺失旗標本身也不證明完整。
- 跨呼叫收集器保留明確狀態、資源所有者及可回收入口。閉包會讀到同一詞法綁定的新值，但先前複製的物件參照、參數或另一 executionContext 不會自動更新；不能只換外層容器就假定所有回呼已改接。頁內 registry 方法先登記唯一 key，回收核對文件／context，不只依賴過期 objectId。
- 先保存整批事件及可證明自有的暫停 ID，再做可能失敗的分類。自有範圍內不匹配請求立即放行，不擅自接管其他工具暫停的回應。攔截生效時持續服務事件，背景工作必須有所有者、截止及清理；不在模型長等待間留下無人處理的請求。
- 實際匹配／持有才算施加網路故障；舊 latestRequested 或一般健康播放不是命中證據。影片恢復須命中影片，音訊案例須命中音訊；不以一方結果代算另一方。
- 有期限觀察器自動截止，第一次停止保存真實終點；觀察終點、工具返回與清理分開。固定節奏落後時跳至下一有效時點，不連續補抓；保存成功再推進持久續讀位置，重讀須去重。晚取回不補造邊界，媒體採樣不補 Network 缺口。[離線方法契約](../scripts/evaluation/README.md#後續取證方法契約)不等於 IAB 能力校準。

### 操作與收束

- 設定只用產品既有命令；恢復前確認欄位仍等於工具最後寫值，保留使用者／其他分頁的新修改，不整體 reset／clear 或覆蓋舊快照。
- 拖曳案例先定位可見進度列，按下後立即核對 dragging，不成立立即釋放。先確保前提失效時能及時解除攔截及按鍵；可同呼叫處理就立即收尾，不能依賴後續模型往返才解除長時間持有。
- 尋位／重載按 [播放器契約](ARCHITECTURE.md#auto-救援與操作所有權) 判斷，不改媒體 getter、新建控制器、強制 tick 或重設預算。合法有限位置不一律需要 opaque proof；有初始化修訂等額外條件時依實際契約核對。SDK reload 需實際操作、修訂及功能狀態，普通 recovered 不代算重載成功。
- 每項自有資源建立時立即登記 finally／對應失敗清理；失聯、截斷或例外時先停止故障，收束自有請求。保存完整方法描述子，只復原仍由工具持有的包裝；原為繼承方法就移除自有遮蔽，不覆蓋其他腳本新包裝。
- 可能提交樣本的非同步尾端全部收束才解除抑制，不能以當下零筆數證明晚到寫入安全。期限內不能收束時，抑制保留至自有文件卸載，其餘自有資源先清理並列 INVALID；不事後清空學習資料掩蓋污染。必要時卸載自有測試分頁後再撤除攔截。
- 清理核對請求、攔截模式、包裝、斷點、訂閱、計時器、設定及受控樣本；未完成則本輪交付不通過，另列殘留與影響，不把責任留給下一輪。獨立成立的原始觀察仍保留。

<a name="解除延遲與剪貼簿寫入"></a>

### 解除受控延遲

停止新增持有，解除自有攔截模式並處理已持有請求，核對後續新請求不再受控；受控樣本抑制依晚到工作生命週期保留。解除故障不等於所有尾端已清理，Network 截斷只限制依賴完整時序的結論。

## 6. 結果、期限與停止規則

| 結果 | 使用條件 |
| --- | --- |
| PASS | 有效觀察與必要證據支持全部斷言，附預期／實際／證據 |
| FAIL | 有效窗口觀察到斷言不符；是否歸因 BiliCDN 另判，傳輸失敗不直接等於腳本缺陷 |
| INVALID | 已開始，但必要前提或證據完整性失效，不作產品判定 |
| 證據不足 | 觀察完成，但必要自然條件或樣本未出現 |
| 未執行 | 因工具、安全前提、時間或範圍限制未開始 |

核心全部 PASS 且清理通過，才宣稱核心完成；必要項目有其餘結果則明示未完成範圍，不刪行、降級或用「待驗收」隱去結果。無關管理器資料與未啟動研究不需另請豁免；條件式缺口仍保留，不外推全部行為或效益。

- 同一版本／倍率／前提先做一個完整窗口，通過且仍適用就不重跑。無效窗須當次明確重跑授權及新前提，不繼承歷史「可再跑一次」。
- 新輪次開跑前凍結總時限、階段上限及清理時段；第一次最小工具檢查為 T0，保存 Asia/Taipei 時間及單調計時。工具往返、等待、更新及歸因都計入截止，餘額不夠下一完整窗口就列未執行，不縮短窗口或占用清理時間。
- 長等待、下載及取檔須有可觀察的外層截止，不以內部 timeout 冒充有界。批准等待／斷線若破壞必要連續性，先作廢相依窗口並清理，不拼接前後證據；能區分的執行與等待時間分列，否則記未量測。
- 確認缺陷時先收束、保存最小案例／正常對照、來源位置與根因，再停止擴大本輪。修復與發布按第 8 節及既有授權處理，不默默附加新瀏覽器矩陣。
- 只剩工具或自然前提問題時，交付本輪終局結果及具體再開條件，不循環重試。P01／P02、BR-01 及其他歷史停止範圍依 TODO，不因文件或能力改變恢復。
- 修復完成、公開產物、安裝行為及效益各自判定；一次未再現不證明舊根因已解決，合法備援或香港音訊 206 不代算指定香港影片供片成功。

## 7. 證據目錄與重跑入口

實際開跑才建立 `.work/iab-testing/<日期>-<版本>-<短提交>-<輪次>/`，保留原歷史目錄。簡單查證可合併成一份報告；下表供分工，不要求全套檔案，也不代表已有一鍵 IAB 命令。

| 檔案 | 按需保存的內容 |
| --- | --- |
| `BASELINE.json`／`CASES.json` | 基準、層級、必要身分／原值、ID、前提、斷言及結果 |
| `TIMELINE.jsonl` | 有界連續事件、時間基準、續讀位置、截斷／遺失狀態與因果順序 |
| `CLEANUP.json` | 自有資源、方法所有權、設定復原及受控樣本核對 |
| `CHECKPOINT.md`／`RERUN.md` | 已完成項目、限制、剩餘前提、工具與操作／清理序列；重跑仍需授權 |
| `REPORT.md`／`screenshots/` | 範圍、五種結果、證據指向、缺口、清理及必要畫面 |

每案記錄 ID、層級、版本、前提、預期／實際、有效性、結果／原因、起訖、證據與清理。本體雜湊、倍率及時序欄位只按斷言需要保存，未知／不適用明列，不為填表追加操作；時限／恢復案例另記合資格 tick、備援／reload／終止的次數與時間。輸出前去除簽名 URL／路徑／查詢／權杖、Cookie、IP 及播放器／核心物件，必要截圖亦核對資料範圍。

重連先讀 checkpoint 並依第 1 節確認連續性；本體相同也不能補齊觀察空隙。舊原件的 VALID＋PASS／FAIL、INVALID＋null 格式與原判保持，不回寫遷移。

## 8. 修復、發布與後續執行

已授權的修復先用正式契約重現，按差異與斷言選 N／S／I；自動驗證及安全審查依 [DEVELOPMENT](DEVELOPMENT.md#依變更選擇驗證範圍)，交付依 [AGENTS 發行規則](../AGENTS.md#發行規則)。verify 不包含安全掃描或 IAB 驗收，公開產物與實際安裝分別記錄；必要來源隔離仍只用 IAB。

需要更新時先用 IAB 既有 [公開 latest 入口](https://github.com/YUIAOI7592/BiliCDN_TW/releases/latest/download/BiliCDN_TW.user.js)，按允許工具完成管理器步驟，再於新文件核對執行身分。使用者已表示更新完成或只要求查證時直接核對，不先下載／重裝。中繼頁、管理器確認與保存副本均不代替實際載入；必要步驟當次受阻且無已授權替代方式時，才說明具體限制與必要人工步驟，不改用外部瀏覽器或繞過閘門。

結束後保存結果及清理，不自動建立排程、補跑歷史矩陣或另開下一輪。
