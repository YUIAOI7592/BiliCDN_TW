# BR-01：失效媒體重設後遺失使用者尋位位置

日期：2026-10-14（Asia/Taipei）。來源與安裝版 **v2.1.24／73d339e**。本報告補充 [政策重評與播放意圖修復](BR01_POLICY_REASSESSMENT_2026-10-14.md)，不改寫既有 Release 或失敗紀錄。

## 結論

**P2 已確認缺陷：暫停時的新尋位尚未播放，媒體失效並將位置重設成 0，下一次明確播放意圖會把這個 0 當成應保存的位置，遺失使用者剛選定的非零目標。** 真正使用者 seek 到 0 仍必須保留，不能將所有零值一律回退到舊 SDK 位置。

獨立重現使用真正 PlayerAdapter／RecoveryController，結果 **1 fail／2 pass**，型別檢查通過。這是新調查契約的預期失敗，沒有加入正式套件，也不能算入已發布的 855／855 通過數量。

安裝版獨立媒體觀察另取得「選到約 46:51，後來從約 35:26 播放」的症狀。該窗口的 Network 收集器出現截斷，因此不作完整故障／傳輸矩陣通過判定，也不聲稱已定位網站最初換核心的網路原因。缺陷確認依據為產品程式路徑與獨立正常對照；安裝觀察是相符的現場症狀。

## 使用者影響與事件順序

1. 同片 Auto 2 倍播放，使用者暫停在 2126.239 秒附近。
2. 可信滑鼠操作選定 2811.003 秒；媒體 seeking=true，控制快照 targetSec=2811.003，userRevision 從 2 增為 3。
3. 影片資料受控延遲、音訊通行；網站換核心，媒體 readyState=0、currentTime=0、paused=true。使用者沒有選擇回到起點。
4. 暫停超過既有門檻、路線合法、真正可見、額度可用時，使用者明確按播放。
5. v2.1.24 正確建立 trusted-player-play，約 4.1 秒後呼叫一次真正 SDK reload，證明本版的播放意圖入口修復生效。
6. 解除故障時立即清空原生攔截模式。後續沒有新的 Fetch.requestPaused；播放器初始化尋位到 2126 秒，控制器先以 seek-interrupted 結束。
7. 明確播放標記後約 8.8 秒出現實際時間／影格進度，後續觀察約 61 秒仍有進度；倍速維持 2，Auto 可正常調整解析度。但開始播放的位置不是使用者最後選定的 2811 秒。

相對時間取自約 100 ms 的獨立頁面採樣，不是網路階段延遲估計。播放按鈕標記在可信 click 前，正常對照的標記在 click 後，兩者不可混作同一統計樣本。

## 根因與既有保護的缺口

| 位置 | 行為與影響 |
| --- | --- |
| [PlayerAdapter controls](../src-v2/adapters/player.ts#L114) | targetSec 是目前觀察目標；seeking／SDK seek 可以更新它，沒有獨立保存可歸屬於最後使用者操作的目標 |
| [媒體與 SDK seek 觀察](../src-v2/adapters/player.ts#L225) | 網站自行尋位也可覆寫 targetSec；這能撤銷過期還原，但不能保證失效後仍記得尚未完成的使用者目標 |
| [PlayerAdapter currentTime](../src-v2/adapters/player.ts#L546) | readyState=0 時優先採有限的原生 currentTime；失效重設的 0 和真正 seek 到 0 在此沒有來源差異 |
| [RecoveryController begin](../src-v2/application/recovery-controller.ts#L198) | 一般播放意圖沒有 stall.targetSec，因此直接以 player.currentTime() 建立 savedPositionSec，重現中保存成 0 |
| [RecoveryController tick](../src-v2/application/recovery-controller.ts#L122) | 非 stall 意圖遇 seeking 即 seek-interrupted；現場初始化尋位也觸發此路徑，必須與真正新使用者操作分開評估，不能全面移除保護 |

最小重現隔離的是「失效重設使 savedPositionSec 丟失」；沒有用 Node 模型冒充完整網站 SDK 初始化順序。現場最終返回 2126 秒由網站初始化採用舊位置，不能宣稱腳本主動 seek 到 2126 或直接 seek 到 0。

## 最小修正方向與必要回歸

需要區分「最後可信使用者尋位目標」與「媒體／網站目前位置」，並將前者綁定操作修訂、媒體、播放器與內容生命週期。只有尚未完成且所有權仍有效的使用者目標可以供恢復採用。真正新 seek、pause、生命週期失效或未知來源變動應維持保守撤銷，不能用舊快取全面覆蓋網站位置。

重載初始化 seeking 是否仍屬本次動作，應由既有 ownedReload 與操作身分證明；不能將所有 seeking 忽略，也不能僅延長 15 秒。必要回歸包括：上述三案、新 seek 取代舊目標、正常網站／Auto 調整、不明來源重設、核心替換、epoch／generation、晚到 reload／play、拖曳及授權撤銷。

本次未修改這段執行期邏輯、未發布新版本。**v2.1.24 的播放入口修復已發布；BR-01 最新位置保護不通過，整體不能結案。** 沒有足夠證據支持改秒數，亦不將本案歸因為原始 87.785 秒自然停滯。
