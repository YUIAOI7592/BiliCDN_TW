## 執行與證據

工具：PowerShell **7.6.5**、Node **26.8.1**、npm **11.19.0**。只使用 Codex 內建瀏覽器；沒有開啟外部 Chrome／Edge、修改瀏覽器設定或停用其他腳本。校準僅在自有 loopback 頁進行，尚未進入指定影片的安裝身分及 P05 操作階段。

| 步驟 | 實際證據 | 判定 |
| --- | --- | --- |
| 隔離層內 PowerShell | `Get-Clipboard -Raw` 讀空；原生 `OpenClipboard` 回報存取被拒 | 讀回無效，不能判成空剪貼簿或產品失敗 |
| 隔離層外 PowerShell | 可讀原文字；序號 557，七種原生格式，原內容只存於同一程序記憶體 | Windows 原資料保存前提成立，未證明與 IAB 共用 |
| 自有服務 | 首次 IAB 連線逾時；改用主機側服務並確認 HTTP 200 後，只重試一次，頁面載入成功 | 新前提成立；初次網路錯誤不列產品缺陷 |
| 真正 IAB 複製 | 聚焦唯讀文字區，Ctrl+A、Ctrl+C | 未代呼叫剪貼簿 API，也未使用會改寫剪貼簿的貼上工具 |
| 真正 IAB 貼上 | 聚焦自有結果區，Ctrl+V；完整來源與貼上內容各 61 字元，逐字相同 | 原生合成文字對照通過 |
| IAB API 只讀核對 | `readText()` 長度 61，與同一來源逐字相同 | 與本輪原生貼上相符，不能代替 PowerShell 門檻 |
| PowerShell 輪詢 | 47 次讀取、5,057 ms，仍為原本 3 字元；序號 557，完整比較不符 | 共同通道不成立，停止實際 P05 |

合成文字包含唯一識別、中文、多行及兩端空白，沒有使用歷史報告字元數。未 trim、刪空行或重新序列化；LF／CRLF 正規化比較也不相等，因此沒有採用換行例外。原剪貼簿文字、HTML、來源 URL 與內部權杖均未輸出或寫入檔案。

`-Raw` 的用途是保留單一多行字串，依 [Microsoft 文件](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/get-clipboard?view=powershell-7.5) 核對；該參數本身不證明跨執行環境共用剪貼簿。

以上僅證明這次執行的 Windows 與 IAB 讀寫觀察不一致，不能推論所有環境永遠不支援，也不能推論 Tampermonkey 的 GM 寫入使用哪個通道。沒有取得實際 P05 入口、傳入報告與呼叫證據，故不修改 `control-center.ts` 或發布推測性修復。

## 何時才能重新執行

目前沒有授權自動開下一個相同窗口。只有取得新的共同通道能力，或使用者明確調整 PowerShell 讀回門檻，才重新安排；不能自行用 IAB API／貼上通過替代既定門檻。

再次校準必須在覆寫前，先完整保存**實際複製通道**的原格式及可用序號；不能假設 Windows 快照涵蓋 IAB。先以唯一合成文字證明原生複製、原生貼上與預定讀回相符，再核對安裝身分並執行一次真實 P05。若有效讀回與貼上均不符且實際呼叫證據完整，才建立正式失敗契約及最小修復；工具或權限仍不成立就停止，不發布推測性修改。
